# Docker Deployment

Docker 主应用经 Nginx 同源入口访问，默认地址为 `http://宿主机IP:3000`。手机与电脑使用同一个服务端，不需要部署第二份应用数据。

首次登录可使用 `INFOS_API_TOKEN` 管理凭据；未设置凭据且没有已配对设备时，可从 `docker compose logs backend` 获取五分钟内有效的一次性管理员配对码。登录后在「分布式 → 服务访问与设备」生成二维码，为其他设备授权并管理设备。填写目标设备可达的 IP 或域名入口；访问端口由容器端口映射或反向代理管理。

`INFOS_WEB_PORT` 控制 Web 发布端口；`INFOS_PUBLIC_URL` 可指定 HTTPS 公开入口。业务和能力端口默认绑定宿主回环地址，外部客户端统一走 Web 入口；额外节点接入可显式配置 `INFOS_BACKEND_BIND`。不要将容器内网地址用于手机二维码。

反向代理应转发 Host、Cookie 和 WebSocket Upgrade，并关闭 SSE 缓冲。普通 HTTP 支持文字、文件和任务；手机麦克风需要 HTTPS。

完整监听、鉴权、开发模式与移动端范围见仓库 `.docs/A04_DEPLOYMENT.md` 第 11 节。

## 数据备份与导入

「数据与备份」导出的 `.infos-backup` 可上传到当前连接的服务端。上传、解包与数据库校验分别显示进度；上传完成后由服务端继续生成预览，可切换页签，返回后继续查看，也可取消尚未确认的导入。服务重启会使尚未确认的预览操作失效，需要重新选择文件；上传途中刷新整个浏览器页面可能中断传输，进度恢复不代表断点续传。

完整恢复仍需确认方案并重启 `backend` 容器后应用，单独刷新网页不会恢复数据。恢复前自动建立恢复点，数据卷挂载点保持原位。上传上限为 20 GiB，总接收时限一小时，连续两分钟无上传进展会结束操作。额外部署的反向代理也需要允许对应请求大小与时限。备份大小是压缩大小，磁盘还需容纳解包内容、当前数据和恢复暂存资料。

## Arca 与 Pictoria

后端镜像同时包含两者的 Host 与 WebUI，主应用会通过控制面管理生命周期，不需要额外暴露子应用随机端口。页面位于 `/applications/arca/` 和 `/applications/pictoria/`；Arca 的浏览器连接走主入口 WebSocket 代理，Pictoria 的画布操作走同源 `/api/applications/pictoria/`。先在主应用完成设备配对，再从应用入口打开；Pictoria 的宿主发布路径也能识别 Docker 挂载模式，不依赖手工追加 `kernelOrigin`。
