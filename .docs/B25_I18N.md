# 国际化

支持 `zh-CN`（简体中文）、`zh-TW`（繁體中文）、`en-US`（English）。首次启动自动选择系统偏好列表中首个受支持语言，列表中没有受支持语言时使用英文。系统设定中的语言配置保存到服务端 `user.language`，已保存偏好优先于自动识别。语言切换不重建会话、不清空编辑内容。

## 分类词库

资源位于 `packages/shared/src/i18n/locales/<语言>/`，按用途与模块拆分，不能合并成一个总 JSON：

- `ui/`：主应用导航、聊天、设置、工具、工作区及其他界面组件。
- `logs/`：服务端各模块与前端日志。
- `server/`：API 返回文案与服务界面元数据。
- `electron/`：窗口、托盘、原生服务及相关日志。
- `apps/arca/`、`apps/pictoria/`、`apps/social/`：子应用界面与日志。
- `errors/`：应用自带的异常提示，按运行端分别维护。
- `common/`：跨端共用的工具名称、界面选项与提示词组件显示名称。
- `platform/`：独立能力节点的终端输出。
- `scripts/`：开发启动、构建、版本同步等脚本的终端提示；通过 `INFOS_LANGUAGE` 选择语言。

`catalogs/` 中的 TypeScript 文件只装配各运行端需要的词库。共享翻译运行时不依赖 Vue、Electron、网络服务或 OpenCC。简中原文作为分类内的稳定查询键；同一句话在不同模块可以有不同翻译。

## 使用

```ts
import { t } from './i18n'
t('ui.chat', '加入队列')
t('logs.agent', '正在执行 {0}', [toolName])
```

动态值通过 `{0}`、`{1}` 插值。先翻译模板，再原样插入参数；不拼接完整动态字符串后做模糊替换。Vue 模板和计算属性中的翻译会追踪语言变化；静态选项使用 getter，避免语言切换后仍保留旧标题。

词库查找顺序为当前语言、同模块英文、同模块简中、调用处原文。未知语言回退英文；中文优先看显式书写体系（`Hans` 为简中、`Hant` 为繁中），没有书写体系时 `TW`、`HK`、`MO` 归到繁中，其他中文归到简中。英语区域归到 `en-US`，兼容 `zh_CN.UTF-8` 等环境标记。回退仅处理资源缺失，不能代替同步补齐三语言译文。

## 同步与启动

- 主应用、Pictoria 和 Arca 的客户端入口共用 `packages/shared/src/i18n/client.ts`。浏览器自动语言来自 `navigator.languages`（不可用时使用 `navigator.language`）；自动探测不写入 `infos.language`，该缓存仅保存明确的语言配置。同源窗口通过存储事件同步，系统语言变化在自动模式下重新选择。
- 主应用完成鉴权后恢复服务端 `user.language`；服务端未配置时清除旧浏览器缓存并恢复自动识别。恢复请求携带本地修订号，用户已切换语言、其他窗口已同步或当前鉴权已失效时，忽略过期响应。原生启动查询也不能覆盖后续语言广播或用户选择。
- 配置单项、批量写入、导入都会更新服务端语言，Gateway 将已保存语言同步到在线客户端。删除配置时服务端恢复自身环境语言，并广播 `language: null`，让每个客户端使用自己的系统语言，避免把服务器语言强加给所有客户端。
- Electron 在 `app.whenReady()` 后、创建启动界面与托盘前初始化语言：本机 `client-language.txt` 的有效保存偏好优先，其次是显式 `INFOS_LANGUAGE`，再按 `app.getPreferredSystemLanguages()` 的界面语言偏好选择。仅在该列表为空时使用 `app.getLocale()`；原生 API 不可用时回退环境与 `Intl` 提示。区域格式不是界面语言来源。语言 IPC 等待这次初始化，避免提前返回默认值。
- 主应用同步已保存配置到 Electron 缓存，清除配置时删除本机缓存；Electron 向托盘、主应用、通知层和内置子应用广播变化。内置子应用只能读取宿主语言，不能修改全局设置。开屏预加载同样按系统偏好启动，并忽略过期查询。
- 独立子应用使用自身浏览器偏好，不依赖 infOS 服务。独立 Node 进程和脚本入口依次使用显式 `INFOS_LANGUAGE`、`LC_ALL`/`LC_MESSAGES`/`LANG`、`Intl` 系统提示，全部不受支持时使用英文。可以用 `INFOS_LANGUAGE=zh-TW` 或 `INFOS_LANGUAGE=en-US` 覆盖部署语言；服务端数据库打开后仍以已保存配置为准。
- Electron 拉起内置 Daemon 时传递当前语言，避免壳层和后端启动日志各自选语言；复用已运行的 Daemon 不改变其启动环境。历史日志不回写，后续日志跟随恢复后的配置。
- 开发启动器使用固定就绪标记，不解析已翻译的日志句子；终端颜色控制符不进入词库。

## 保持不变的内容

用户消息、Agent 回复、角色人设、提示词正文、用户自定义名称、工作区路径、模型 ID、协议字段与第三方原始输出不属于界面词库。不得通过 DOM 全页替换或任意字符串替换来翻译这些内容。

内部异常原文和错误码保持不变，防止影响重试与恢复判断；只在 API 错误返回或界面展示边界匹配项目登记的错误模板。工具函数名与模型可见协议保持不变，用户显示名称单独翻译。

## 词库维护与排障

词条位于 `packages/shared/src/i18n/locales/<语言>/`，按用途分类；`catalogs/` 提供分类目录，运行端通过各自 i18n 入口消费。前端入口为 `packages/frontend/src/i18n/index.ts`，后端为 `packages/backend/src/lib/i18n.ts`，Electron 为 `electron/main/utils/i18n.ts`。翻译在本地词库完成，运行与构建不调用翻译服务或临时迁移脚本。

新增/修改模板同步维护简中、繁中、英文，保留相同插值编号。译文直接修改对应分类 JSON；不通过大段动态句子的模糊替换维护翻译，也不把简繁转换或英文初译视为完成校对。运行时回退只负责兼容缺失条目。

排查切换语言后残留旧文字时，先检查值是否在初始化时固化，再检查模块与词条注册、语言同步和插值。协议标识与内部错误码不翻译，业务判断不能依赖本地化句子。核心回归入口为 `packages/shared/tests/i18n.test.ts`、`packages/shared/tests/clientLanguage.test.ts` 与 `electron/main/utils/i18n.test.ts`。
