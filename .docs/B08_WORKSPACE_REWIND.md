# 对话撤回与工作区恢复

## 恢复范围

撤回目标轮次会连带撤回之后的轮次；删除会话覆盖该会话的全部轮次。工作区按文件恢复到这段对话开始前的内容，消息随后软删除。

当前记录入口为对话中的 `write_file` 和 `edit_file`。后台任务、终端或外部程序写入、工作区外写入，以及尚未接入记录入口的删除和重命名，不具备完整的文件恢复记录。

## 连续性与后续修改

- 同轮同文件保留首次原文和最终哈希；合并时比较前一次结果与后一次写入前状态。发现差异后，本轮永久标记为不连续。
- 快照提交还会核对工具实际返回的写入前后哈希；捕获后或读盘前夹入其他修改时，不把它们归为可恢复的 Agent 连续历史。
- 跨轮按对话轮次排序，检查每次修改前状态是否等于前一轮修改后状态。任意一处断开，保留整份文件。
- 磁盘版本不等于最后一次记录结果时，保留整份文件。恢复前会重新检查，临时文件替换前还会再检查一次。
- 最早一轮创建的文件，在完整连续恢复时删除；中途夹入人工改动时保留。
- `0006_workspace_rewind_safety` 为旧快照标记未知连续性。旧数据无法还原同轮中间过程，因此撤回其聊天时保留文件，不自动覆盖。

这些检查不进行文本合并；保留文件时，Agent 与人工已有的修改都保留。

## 编辑缓冲与界面

统一撤回入口向工作区发送可取消的预检事件，检查当前及暂存角色在相关路径上的未保存内容。需要先保存或关闭这些缓冲后才能撤回。各撤回入口共用工作区刷新事件。

确认框分别显示后续修改、历史不连续、记录不完整和无法安全读取的保留原因。完成后的文件数量使用实际结果重算。

## 失败恢复

同一角色工作区的撤回串行执行。恢复文本通过临时文件写入并替换，避免部分正文写入；会话及消息的整体软删除使用数据库事务。

本次操作在内存中保留受影响文件的撤回前版本。文件恢复或消息删除抛错时，尝试补偿已经修改的路径。补偿只覆盖仍等于本次恢复结果的文件；再次变化的文件保留当前内容，其撤回前版本另存到对应角色目录的 `rewind-recovery/<操作ID>/`，包含 `recovery.json` 和原始字节备份。

该补偿处理运行中的可捕获错误，不提供进程崩溃后的自动恢复，也尚未提供撤销回滚本身的入口。任意外部进程的文件写入不受应用内串行队列约束。

## 实现入口与一致性维护

文件检查点由 `packages/backend/src/services/workspace/workspaceCheckpointService.ts` 维护，前端撤回入口为 `components/chat/ConversationRewindDialog.vue` 和 `composables/chat/useConversationRewind.ts`。历史删除还影响队列、角色状态与工具原件，分别遵循 [B26](./B26_CONVERSATION_QUEUE.md)、[B10](./B10_CHARACTER_STATE.md) 和 [B01](./B01_PRODUCTIVITY_RUNTIME.md)。

修改时重点保护同轮首次/最终版本、外部修改冲突和补偿恢复。不能通过简单覆盖文件再删除消息来模拟原子撤回；补偿目录须保留可恢复的原始字节与操作记录。
