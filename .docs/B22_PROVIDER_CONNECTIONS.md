# 服务商连接与模型卡片

服务商连接、模型卡片和模型指派分开保存。连接管理位于「模型配置 → 服务商连接」，使用现有像素组件及主题变量。

## 使用方式

1. 添加模型卡片，默认使用「独立配置」，直接填写 API 地址、密钥和模型 ID，无需先创建服务商连接。模型名称留空时使用模型 ID。品牌模板预填地址、协议和认证方式，之后仍可自行调整。
2. 多张卡片需要复用配置时，可在连接管理中新建连接，再从卡片中选择。同一品牌可以创建多套连接。获取列表失败或服务商不支持列表时仍可手动填写模型 ID。
3. 卡片上可直接切换连接，保留模型 ID、采样参数、能力声明及任务/角色指派。跨服务商切换后，用户仍需选择该服务商支持的模型 ID。
4. 默认完整继承连接的地址、密钥、协议与认证方式。「自定义此模型的连接」会复制当前连接作为编辑起点，此后该卡片使用自身完整配置，不再将地址和密钥分别继承。关闭覆盖后恢复完整继承。
5. 连接可直接重命名、替换密钥或清空密钥。API Key 可留空，即使认证方式为「API Key」，也会正常发起请求并省略认证字段，不发送空 Bearer、空 API Key 请求头或空密钥查询参数。「无需认证」会忽略已保存的密钥。是否需要认证由实际接口决定，上游拒绝会按正常请求失败处理。
6. 编辑器可从共享连接切回「独立配置」，会完整复制当前有效连接，之后单独保存；独立卡片清空密钥后不会从旧全局配置补回。旧卡片原有的兼容读取规则保留。

保存前校验必填模型 ID 与数值参数，空白可选数值保存为 `null`。后端返回的字段错误在编辑器内显示，失败时保留表单；保存期间禁用重复提交和关闭操作。

首次通过模型配置接口成功保存卡片时，若此前没有模型且主模型指派缺失或为空，自动将该卡片选为主模型。模型创建与默认指派在同一 SQLite 事务提交，保存后界面同步刷新主模型标记。后续新增模型不会覆盖主模型，也不会在修改已有卡片时自动改选；免密模型同样适用，不额外调用模型测试接口。

连接列表仅返回是否已配置密钥，不返回密钥本体；编辑接口与原模型编辑接口一样，只通过已鉴权的管理 API 回填密钥。

## 检查与引用

- **地址可达**：只检查网络能否收到 HTTP 响应，404/401/403 也可能表示地址可达，不表示认证或推理成功。
- **获取模型列表**：按连接选择的协议查询，失败保留真实错误，不伪造官方模型列表。
- **模型卡片测试**：按该卡片真实生效的连接、协议和参数发起一次短回复请求；不进入其他模型的回退链。卡片内展示测试结果与耗时。
- 保存连接会使模型注册表缓存失效，新请求使用最新连接；已经开始的请求继续使用其配置快照。
- 删除被引用的连接前显示所有模型引用，必须选择替换连接。引用更新和删除在同一 SQLite 事务内完成，外键阻止悬空引用。独立覆盖卡片替换引用后仍保留自身覆盖；卡片直接切换连接则明确关闭覆盖。
- Embedding/Reranker 继续使用各自已激活的专用配置，列表查询不再偷偷拼接某个品牌的全局地址和密钥。

## 持久化与旧配置迁移

标准结构迁移 `0019_provider_connections` 创建 `provider_connections`，模型通过稳定 ID 引用，重命名不影响引用。

- 已配置的旧 `global.<品牌>.apiBase/apiKey` 导入为品牌对应的共享连接。
- 原来完整继承的模型绑定对应连接。
- 有独立地址或密钥的模型单独生成同名连接，按旧规则计算一次有效地址与密钥，保留混合配置原来的实际行为；不自动合并不同模型的独立连接。
- 旧自定义模型保存过的 Anthropic/Gemini 协议迁入独立连接。旧版没有成功保存的协议无法凭空恢复，仍需用户在连接中选择。
- 保留旧配置键及模型原始字段作为兼容数据，新的连接引用优先且不会回退补入旧密钥。缺失的引用明确报错，不重新绑定其他服务商。

迁移 `0020_provider_connection_names` 清理旧自动名称中的迁移后缀，仅修改符合生成规则的名称，不修改用户自定义名称、连接 ID、密钥或模型引用。已有安装在下次服务启动时应用。

所有主模型、角色/任务模型、回退模型、模型测试及远程列表查询均解析连接的实际协议；品牌标签不再代替协议。

环境变量兜底只要求 `PERO_LLM_MODEL`；`PERO_LLM_API_KEY` 同样可省略，地址由 `PERO_LLM_API_BASE` 指定或使用协议默认值。角色解析器不会因为空密钥将已选模型视为不可用。

## 自定义地址约定

填写完整 API 根地址，例如 `/v1`、`/api/v3`、`/anthropic/v1` 或 `/v1beta`。已有路径原样保留，只有纯域名才补对应协议的默认版本路径。Chat Completions、Responses、模型列表、Anthropic 和 Gemini 共用地址拼接规则，避免版本路径重复。

## 会话快捷配置

聊天输入栏可选择已配置的模型卡片与思考强度。通过 `threads.model_config_id`、`threads.reasoning_effort` 持久保存，仅影响当前普通桌面会话；模型默认跟随全局主模型，强度默认跟随卡片。删除已选卡片时外键将选择恢复为空。明确指定模型的委派任务、后台线程和社交仍保留原有模型解析规则。

`GET/PUT /api/chat/threads/:id/model-settings` 返回不含密钥的卡片摘要与有效能力。生成期间禁止修改；上下文预算、能力显示和 ReAct 执行共用解析结果，执行快照仅存于服务内部。主模型回退链继续生效，会话强度按每个候选模型的能力校正。档位、Gemini 4 兼容映射由共享模块统一提供，与模型配置页一致。

输入栏的思考图标随有效档位提高增加浮动、光晕与闪点；关闭思考不循环动画，减少动效和系统减少动态效果偏好会停用循环动画。

## Gemini 原生音频输入

模型卡片上的「原生音频输入」仍由用户手动开启，不根据模型名称自动判断。只有开启该能力且有效连接协议为 `gemini` 时，当前轮音频才进入模型请求；自定义 API 地址复用 Gemini `generateContent` / `streamGenerateContent` 与 `inlineData` 协议。

带原音的请求只允许回退到同样手动开启音频输入的 Gemini 协议卡片。开关关闭或协议不匹配时，上传音频仍可保存、播放，但当前轮只提供文件引用，提示词明确说明模型未听取原音。

当前使用内联音频，每轮原音合计最多 12 MiB，整个 Gemini 请求最多 20 MiB；超限单文件保存为引用。暂未接入 Gemini Files API、实时语音或原生音频输出。模型是否实际支持音频仍以所选服务的响应为准。

## 维护入口与排障

连接解析与迁移由 `packages/backend/src/services/model/providerConnectionService.ts` 负责，持久化入口为 `packages/backend/src/repositories/providerConnection.repo.ts`，前端管理入口为 `components/dashboard/ProviderConnectionsDialog.vue`。继承共享连接的卡片保存稳定引用；独立配置或显式开启完整覆盖时保存自身连接配置，不能把字段继承与完整覆盖混合解析。

修改连接解析时保护旧配置迁移、完整覆盖/清空密钥、删除替换事务、稳定引用和不同 API 根路径。请求失败应先核对最终协议与解析后的路径，再检查能力开关和服务端响应；品牌图标与模型名称不能作为能力或协议依据。
