# 消息队列与即时交接

## 用户交互

主对话和工作区协作栏共用队列。输入栏在执行期间仍可编辑和提交，发送按钮显示「加入队列」，停止按钮独立保留。输入栏上方展示当前执行摘要与尚未发送的消息，可折叠、编辑、移除、上下调序、暂停派发或发送待排消息。中断或失败的已发送消息不会重新列入待发送队列。

只有确有等待发送的消息时显示队列：单条正在执行的请求，以及首次提交尚未被执行器领取的单条消息不显示队列；执行期间新增的待发消息、真正的多条排队或已暂停的待发消息会显示。断线但没有待发内容时也不显示空队列。

每条待发消息提供立即提交、退回输入栏编辑、上移、下移及删除的小按钮。退回编辑会先原子改为 `draft`，停止派发并保留原文、附件、识图模式和工作区材料；输入栏接收后才确认移除服务器草稿。取回失败或关闭页面时，未确认的草稿仍在服务端，之后可以重新取回。已有输入内容保留并与取回文本合并，不创建聊天消息对。

队列状态使用简短文案和图标，长篇上游异常留在日志中；失联显示重连图标，失败显示警告图标。

「立即提交」将指定消息移到队首并请求交接。正在生成的模型请求会取消；已开始的工具先回传结果。其余工具调用补齐未执行结果，未完成的参数草稿不会执行。旧回合完成持久化和资源交接后，在同一 Thread 开始携带新指令的回合。用户的新指令是正式持久消息，不使用单条、可覆盖的临时指令槽。

本功能覆盖 desktop Thread；据点群聊与社交应用继续使用各自的批次和编排规则。

## 持久化与派发

主线重置时清理旧队列输入并推进 Thread 代次。新队列项保存服务端确认的 `expectedGeneration`，派发前复查。正在退出的旧回合按自身占用身份结算，保留新代次的运行资源。主侧契约见 [主侧会话](./B26_MAIN_SIDE_THREADS.md)。

- `conversation_queue_threads` 保存暂停状态与原因。
- `conversation_queue_items` 保存稳定提交身份、目标 Thread/角色、用户原始输入、附件引用、顺序、版本和执行状态。旧工具检查点字段仅保留结构兼容，启动时清空，不再写入或注入。
- 用户显式入队、原子重生成入队（`enqueueRegeneration`）、编辑、调序、删除、取回草稿与暂停事务通过 `durableQueueWrite` 在 SQLite WAL 下临时提升至 `synchronous=FULL`，提交完成后才向前端确认；队列内部领取、结算与启动恢复复用连接默认的 `synchronous=NORMAL` 事务。未正式派发的输入不进入历史或模型上下文。
- 入队使用客户端 UUID 幂等；编辑、删除与调序要求匹配版本，多端过期操作返回冲突。
- 每个 Thread 同时只运行一个前台对话。队列也避让已有后台任务与 Kernel 执行，使用与普通 SSE 相同的 `runChatStream` 进行流式输出、消息保存及结算。
- 附件随入队请求校验，仍被队列引用的附件不能由上传清理接口删除。工作区上下文在提交时捕获，实际编译沿用文件版本校验和失效回退。
- 观察连接中断不取消后台执行，也不重新 POST 原消息。实时 Surface 可单独获取快照，恢复后继续接收增量。
- 观察请求绑定当前会话、角色与读取身份，切换、历史变更或订阅释放时取消在途读取，迟到响应按原身份丢弃。`NOT_FOUND` 使已失效会话退出观察，清理本地快照与窗口选择，再恢复该角色的有效会话。网络故障和鉴权恢复沿各自的重连路径处理。

## 停止、失败与异常退出

用户停止、执行失败、循环切断或桌面操作暂停，都会保留后续未发送消息并暂停派发。用户可以发送这些待排消息，或明确立即提交某一条新指令；取消请求仍未结算时不会强制并行启动。

正式派发后，先校验会话归属和附件引用并保存用户原文（或开启重生成分支），随即通过 `onInputAccepted` 提前打开 `ConversationSurfaceSession` 并推送首个 `surface.open` 思考帧，使前端在图片转述与并行上下文编译完成前即可接入实时运行态；待 Kernel Execution 建立后再绑定 `executionId`。主线以队列身份和代次建立独立输入及逻辑执行，准备失败记录到执行结果。侧线继续关联已有消息对。尚未创建 Kernel Execution 时同样推送失败 Surface，前端可以读取已落盘的原文和失败原因。临时输入和输出沿用调用方声明的保存约定。会话读取也纳入同一失败结算路径，读取失败时发出失败 Surface，并释放对应运行占用与实时队列状态。

启动时检查所有未结算条目。主线以持久执行的 `completed / waiting` 状态确认完成，侧线以稳定消息对中的有效回复确认。其余执行中条目标为中断，未发送消息保留并暂停等待用户处理。主线等待事项由后续输入创建新执行接续，契约见[主侧会话参考](./B26_MAIN_SIDE_THREADS.md)。

已移除中断项的「继续处理」入口及后端行为。不创建合成用户输入、不复制旧请求、不注入旧队列检查点，也不为此创建额外消息对。用户需要接着交流时，自行在聊天栏发送后续指令，使用正常的历史上下文。队列没有其他未发送消息时，新输入可以正常派发，不会被旧中断条目卡住。

启动时取消旧版本遗留的、尚未发送的合成续接项，不修改已经存在的聊天消息。

历史编辑会暂停队列并更新版本。主线的单条消息操作保留独立待发送输入，侧线的分支回滚撤销该分支尚未发送的消息和编辑草稿。主线重置清理旧代次待处理项，整条侧线删除同时清除队列内容。前端按服务端版本更新队列。

历史变更期间持有会话级派发锁，并发入队、调序或恢复派发会被拒绝；执行器完成异步查询后也会复查此锁。成功和失败路径都会释放锁，避免其他客户端在回滚过程中重启旧分支队列。

SQLite 的持久保证仍依赖宿主磁盘兑现同步写入；磁盘故障或系统返回写入错误时，接口不会确认入队成功。

## 维护入口与并发约束

`packages/backend/src/services/conversation/conversationQueueService.ts` 负责领取、派发与恢复，`repositories/conversationQueue.repo.ts` 保存队列和版本；前端 `components/chat/ConversationQueue.vue` 与 `composables/chat/useConversationQueue.ts` 消费权威状态。

修改队列时保护幂等、并发版本、顺序、失败暂停、在飞取消以及回滚派发锁。用户后续输入须按原文派发，旧合成续接项按兼容规则退出，不能额外生成消息对。排查卡住条目时分别核对持久状态、当前 Execution、领取版本和锁，不以客户端列表为空推断已处理。

已有回归入口为 `packages/backend/tests/unit/services/conversationQueueService.test.ts` 与 `repositories/conversationQueue.repo.test.ts`。任务结果入队与投递状态的区分见 [B20](./B20_PROACTIVE_WORK.md)。
