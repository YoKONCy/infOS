# 文档知识库

## 范围与入口

主应用「知识库 → 文档知识库」管理所有角色共享的资料。当前支持 UTF-8 文本文件、粘贴文本和 HTTP/HTTPS 网页正文；PDF、DOCX、需登录或脚本渲染的网页暂不支持。文本输入与网页响应有 8 MiB 的传输保护上限。

采用事实库的资料列表与详情布局，复用现有深浅主题令牌。可导入、更新、删除、重试整理、重建索引，以及手动检索。原文按需展开，长部分使用字符游标继续读取。

## 入库

1. 统一 BOM、换行，使用本地 `o200k_base` 计数。
2. 少于 **10,000 Token**：LLM 整篇输出摘要与关键词，保留一个部分。
3. **10,000–400,000 Token**：LLM 按语义整理为少量部分，通常 2–8 部分，防御性上限 24 部分。
4. 超过 **400,000 Token**：拒绝入库，提示先手动切分。
5. 按配置对每部分的**摘要**进行 Embedding；未配置时跳过，失败时保留文本检索能力。

模型在「模型配置 → 任务指派 → 知识整理」指定，配置键为 `model.task.knowledge`，未指派时沿用主模型。已知模型上下文窗口不足时在请求前报错，不以截断资料的方式继续整理。

提供给模型的编号段落只是定位锚点，不是固定切片。模型返回编号区间、标题、摘要与关键词；程序检查区间连续覆盖全文，再从原文截取各部分。格式错误允许一次修复，仍不合法则保留来源并标记失败。

## 存储与生命周期

- `knowledge_documents` 保存原文、来源、版本、任务状态与错误。
- `knowledge_parts` 保存位置、摘要、关键词及带模型指纹的摘要向量。
- `@data/knowledge/knowledge.tdb` 是 BM25 与向量检索的派生索引。
- `@data/knowledge/sources/<partId>.txt` 是供现有 ripgrep 检索的派生文本。
- 采用标准 Drizzle 迁移 `0004_document_knowledge`，含 journal 与 snapshot；无新增运行时建表分支。

整理任务通过 `KernelScheduler` 后台队列执行，串行组织资料，界面关闭不影响整理。状态为待整理、整理中、可检索、失败。原文与各部分只有在整理完成后一起发布。

更新使版本递增，旧版本暂时退出检索；删除、更新和出厂重置取消相关任务，旧任务不能发布到新版本。重启后恢复派生索引、重新派发待整理任务，将中断的整理任务标记为可重试失败。

向量指纹由 API 基址、模型名和维度组成。换模型后不混用旧向量，资料仍可文本检索；点击重建索引即可重新向量化。重建不重复调用摘要 LLM。重置角色记忆不删除导入资料；恢复出厂设置会清除资料及索引。

## 单一 Agent 工具

只注册 **`search_knowledge`（检索知识）**。没有独立的原文展开工具，自动召回默认关闭。

至少有一个整理完成且包含可检索部分的文档时，工具描述附加简短的可选查阅提示，不要求每轮查询。空库不提供该检索工具或额外提示；事实库的查询和写入工具始终保留，只有存在有效事实时才附加类似提示。

## 可选自动召回

知识库管理面板的事实库与文档知识库分类分别提供自动召回开关，默认均关闭。配置保存在 `knowledge.recall`，不改变事件记忆 RAG 配置，不调用 LLM 重新总结资料。

- 文档开启时，按当前输入执行 BM25 和可用的摘要向量检索，最多注入三条已有摘要，正文与元数据预算为 1000 Token。自动向量召回使用更保守的相似度阈值；等待最多 2.5 秒，失败或超时后仍可使用本地文本结果。
- 事实开启时，按对象名称、别名及文本匹配召回，最多四条有效事实，正文与元数据预算为 650 Token。保留事实 ID、对象、来源与观察时间；已被取代、撤回或遗忘的记录不参与，无关的零分候选不注入。
- 结果分别进入本轮 `<turn_context>` 的 `<knowledge_context>` 和 `<facts_context>`，与 `<long_term_memory>` 分离。无命中不渲染空标签，资料内容经过 XML 转义。自动召回不参与事件记忆的图扩散、学习或反馈链。
- 召回遵守当前通道、模式和会话工具权限；禁用对应查询工具时不自动读取该库。预算预览和主应用 Realm 执行不触发自动召回，取消请求会中止召回，一类资料失败不阻塞另一类或正常对话。
- 原样保存的内置本轮上下文模板可随版本升级；用户改写的模板保持原样。自定义框架可使用 `knowledge_context` 与 `facts_context` 变量，放入自己的动态 XML 区域。

## 工具检索参数与结果

| 字段          | 含义                                                                  |
| ------------- | --------------------------------------------------------------------- |
| `keywords`    | 最多 20 个关键词或短语，BM25 召回，并在有有效索引时进行查询 Embedding |
| `regex`       | 可选 ripgrep 正则，匹配原文                                           |
| `limit`       | 默认 5，最大 20                                                       |
| `document_id` | 限定一份资料                                                          |
| `expand`      | 默认 false；true 时返回所选部分的原文                                 |
| `part_ids`    | 用先前返回的片段编号精确展开，最多 20 个                              |
| `offset`      | 展开单个指定片段时，使用上次 `nextOffset` 继续读取                    |

BM25、摘要向量与正则分别召回，按 RRF 合并排名、去重，过滤非当前可检索版本后取前 n 项。通常的全库关键词与向量候选各最多 200 项；限定文档时扩大候选范围，避免目标资料被其他文档挤出。

默认返回标题、摘要、关键词、来源、文档版本和原文节选。正则或字面关键词命中时节选围绕命中位置；只有语义命中时预览该部分开头。原文不会经 LLM 改写。ripgrep 字节位置会转换成字符位置，避免中文、emoji 导致摘录错位。

每次结果总预算 **24K Token**，包括 JSON 转义、元数据及响应封装；到预算时明确返回 `truncated` 和继续读取的游标。向量不可用时保留文本检索；同时提供关键词时，正则失败也可退回关键词检索并返回警告。

工具结果接入现有 `ToolContextService`：当前执行与近期对话可消费正文，审计只保存来源、请求与规模，退出消息窗口或重启后按来源重读。资料版本变化后旧缓存失效，不再作为当前资料注入。知识检索不经过高级记忆管线或 ContextRNN。
