# 角色主动行为、计划与跟进

## 运行归属

陪伴和自主行动默认取得角色唯一主 Thread，用户在某个窗口选择 SideThread 仅改变该窗口的交互目标。任务回填携带创建时的目标代次，主线重置后旧交付停止回填。主侧生命周期见 [主侧会话](./B26_MAIN_SIDE_THREADS.md)。

桌面 `manage_task.create` 保存原会话并启用结果回填。任务完成、失败或需要处理时，通过现有 Outbox 投递通知与受控历史事件；完成和失败另外进入持久会话队列唤醒。队列使用稳定投递编号去重，等待当前回合退出后处理，不伪造用户消息。任务事件不能退回编辑或改写为用户请求，可以取消本次自动唤醒。历史编译器将 `background_task_result` 作为数据投影到原生与模板历史，普通系统消息继续被过滤。执行完成、投递与队列消费分别保留实际状态。

权威任务结果不再截断到 2000 字，聊天通知使用有限摘要；`manage_task.get` 提供 `resultOffset/resultLimit`、总字符数和下一页偏移。等待依赖任务后会收到终态、结果摘要、错误、产出引用与验证等级，依赖失败交还父任务判断，不直接丢弃其上下文。主动回合派发标记为 Agent 发起，不能标成新的用户请求。

主动回合由 KernelScheduler 调度并复用 ConversationTurnService；定时 Agent 任务与跟进继续由 BackgroundTaskService 执行。计划、建议保存业务状态；ContextCompiler 负责按当前 Thread 编译输入。

## 全局默认、角色覆盖与 Thread 模式

`ProactiveService` 在 `proactive.settings` 保存全局默认模式 `off / companion / autonomous`、默认关闭的 `strongholdActivity` 与 `agents` 角色覆盖。两项分别继承，缺少字段时实时读取全局默认，角色可以单独指定模式或据点自由活动。全局关闭时，角色明确开启的策略继续生效。总览和任务中心共用同一入口，角色列表带头像，两项设置分别保存。

`PUT /api/scheduler/proactive` 修改全局默认与公共调度参数。`PUT /api/scheduler/proactive/agents/:agentId` 修改已存在角色的覆盖，字段传 `null` 移除该项覆盖。服务端串行合并角色补丁，避免多个客户端覆盖其他角色的设置。旧陪伴 API 提供角色参数时修改对应角色，省略时修改全局默认。

交互模式 `minimal / chat / work` 属于 Thread，主动模式决定唤醒目的。实际工具范围由角色能力、场景、交互模式、执行作用域与审批权限共同确定，桌宠交互遵循其会话设置。极简模式提供更新心流与完成任务，主会话另有 `conversation` 连续交流协议，准确范围见 [B09 交互模式](./B09_THREAD_INTERACTION_MODE.md)。工作模式注入已有工作状态和工具原件，极简与聊天使用精简上下文。

调度按已启用角色的有效策略轮转，执行时取得角色唯一 MainThread。据点自由活动与私聊主动唤醒共用空闲调度，结合上次活动场景选择当前机会，据点可进行聊天、走动和邀请。房间已有待处理交流时优先处理原请求。角色心流的持久归属与场景近期原文见 [主侧会话](./B26_MAIN_SIDE_THREADS.md)。

配置、轮转位置、角色冷却、条件等待与最近记录由 ConfigRepository 保存。角色静默后逐步延长空闲等待，后续规则检查可以直接跳过等待和忙碌角色。私聊主动唤醒沿用原有计数账本，据点自由活动采用空闲机会、定向请求与条件恢复。实际任务及交付仍由任务领域保存。

- 智能陪伴：用户活动重新计时，连续未回应逐渐延长间隔，深夜继续降频，不再达到五次后永久停住。
- 自主行动：结合角色记忆、既有授权事项和执行会话判断值得推进什么。最新资料继续通过现有联网搜索和网页工具取得；没有单独的 URL 登记或信息源监控链路。行动偏好可留空，不作为开启条件。
- 既有私聊计数独立于单次 Kernel 执行。智能陪伴最多三次模型请求，自主行动和据点沿用三十分钟、六十四次模型请求、一百二十八次工具调用的执行约束。
- 切换或关闭会先取消并等待旧主动回合退出。HTTP、SSE、Gateway 和语音统一从对话入口记录用户活动；陪伴回合以及与用户争用同一角色的自主回合让出执行，与用户在哪个 Thread 发言无关。
- 主动唤醒输入不伪造成用户消息，回复、工具观察和工作原件正常保存；主动记忆工具仍提交真实写入。界面保留当前阶段和最近记录，调度细节默认折叠。

## 据点接话与条件等待

群聊规则选人。用户点名按目标顺序处理，普通用户发言优先接续最近交谈者；角色普通分享积累亲历。`stronghold_summon_agents` 的成功结果为已提交发言创建定向回应请求，接收者按自己的据点自由活动设置参与。房间按顺序处理请求，各角色通过同一主线运行时占用与私聊协调。

回应请求保存在来源消息的 `replyIntent`，目标固定主线与代次，队列、已处理者及重试现场持久保存。一次执行按角色、来源消息和主线代次复用已发布回复，同一角色可以回应同一交流里的不同消息。消息与亲历同事务提交，Outbox 唤醒及周期恢复共用同一请求身份。

`finish_task.next_activity` 可选 `rest / wait_message / wait_task`。角色在实际执行中一并决定接下来的等待，省去独立模型判断。等待记录携带主线、代次、来源执行、场景和消息位置。`wait_message` 指定 `senderId`，私聊等待用户，据点可等待在场且开启自由活动的伙伴或用户。等待伙伴回答时，正式发言自动持有定向请求。`wait_task` 引用当前角色的真实任务。条件等待期间跳过空闲推理，后续明确输入仍可正常处理。

据点消息通过真实来源与消费位置匹配等待，先持久化回应请求再结算等待，重复事件沿原来源去重。任务等待匹配真实终态，已有 `resume` 交付沿原目标会话接续，其余显式等待由对应场景接收结果事件。重启重查消息与任务事实，主线代次、来源失效或离场使旧等待退出当前调度。后台持久任务继续使用 `task_result`。

逻辑备份导入恢复角色覆盖、心流和历史资料，角色映射同步重写设置中的键。历史待回应请求沿既有导入策略结算，主动等待由导入后的实际执行重新登记。进程重启使用本机持久等待继续匹配真实事件。

据点执行可以通过空 `finish_task.reply` 静默结束，公开消息取最终回复。实际工具与结果保留审计来源。房间生活／协作模式切换、多人分工与验收属于后续协作规划。

- `set_reminder`：创建提醒、话题、预设反应，绑定调用角色和来源对话。
- `schedule_follow_up`：安排一次未来检查，须给出原因、具体检查内容和时间。
- `suggest_next_step`：保存待处理建议。用户查看依据和行动内容后，可以采纳或忽略。

## 生命周期

计划：`pending → dispatching → completed / dispatched`。派发失败退避重试，三次失败后进入 `failed`；用户可以重试或取消。领取带令牌和一分钟租约，过期领取者不能覆盖新的结算。所有角色的到期计划均被检查。

跟进和定时 Agent 任务在后台任务持久化后记为 `dispatched`；实际执行状态以关联后台任务为准。计划使用服务端生成的固定去重键，进程中断后再次派发会找到原任务。已入库但未提交 Scheduler 的排队任务在启动时补交；执行中断的任务保留检查点，供用户手动继续。

建议：`open → accepting → accepted`，或 `open → dismissed`。采纳意图先保存，后台任务使用固定去重键；扫描会恢复进程中断留下的 `accepting`。只有采纳接口会把建议变成用户发起的工作。

通知使用稳定通知 ID 与现有持久通知设施。外部副作用仍遵循工具自己的审批和幂等契约，不宣称跨进程恰好执行一次。

周期计划使用可选 `repeatIntervalMinutes`。每次成功派发后计算下一次未来时刻，跳过错过的时段；每次的去重键包含本次到期时间。前一次关联任务未结束时延后检查，不能重叠派发，也不消耗失败次数。暂停会取消活动任务，恢复从未来时刻继续；取消或暂停清空领取令牌，迟到结算不能覆盖用户操作。周期计划独立于全局主动模式开关。

定时 Agent 任务创建时固定来源与结果 Thread，派发时复制该会话的执行模式、审批模式和禁用工具；后续会话切换不修改已派发的后台任务。任务中心提供一次、每小时、每二十四小时和每七天的固定间隔选项，不按日历或 Cron 计算。

## 预算与权限

一次性跟进限一分钟至七天，单角色最多五个待跟进事项、每 UTC 日最多安排二十次，取消仍计入每日次数。执行预算为两分钟、八次模型调用、十二次工具调用。

`follow_up` 是请求级能力范围，只能与现有桌面 Channel 权限取交集。允许文件读取、查询、网页读取、截图和提出建议；禁止文件写入、命令执行、外部消息、MCP 和动态技能加载。跟进需要额外行动时提出建议，由用户采纳后进入普通后台执行。

全局陪伴与自主行动不再强制 `ambient` 作用域，允许安静结束；失败和静默结束后仍按间隔冷却。用户安排的跟进维持独立的只读范围。

## 前端

`GET /api/scheduler/activity?agentId=...` 聚合已有后台任务、计划与建议。桌宠和任务中心共用活动数据，按场景分别呈现。

- 桌宠浮窗只在等待用户确认、存在待采纳建议、计划派发失败或有未读失败结果时出现；空闲、普通执行中和未来计划不显示常驻浮窗。提示使用小幅深色半透明面板，默认收起详情，可手动关闭；同一批事项不会因轮询再次弹出，新事项到来后恢复提示。
- 任务中心的活动区聚焦需要处理的事项，完整任务与历史保留在原有列表；建议、确认和失败重试使用统一的细边线、状态图标与操作层级。定时任务创建表单默认折叠，创建后收起。
- 近期工具结果由统一上下文窗口和预算管理，移除独立会话材料入口；输入台仅展示本轮显式附带的文件、选区和终端。工具来源与预算降级信息保留在诊断清单中。

Gateway 只通知投影失效，业务数据通过 REST 重读；角色切换丢弃旧响应，KeepAlive 隐藏停止刷新，权限或角色不存在时停止自动重试。等待审批的任务可以查看请求、填写附言并同意或拒绝本次操作。

对话中的 `manage_task` 和 `interact_with_social` 工具以结构化返回的任务 ID 提供详情入口，NIT 子调用分别关联各自任务；技术详情保留独立入口。任务详情采用右侧面板，分为概览、执行记录和运行信息，集中展示结果、计划、父子任务、预算与投递状态。问答和审批始终置顶且只渲染一次。详情打开期间定时重读，关闭或页面隐藏使旧请求失效；刷新不覆盖正在编辑的任务要求，保存继续使用编辑起始版本进行并发校验。

历史查询通过 `GET /api/background-tasks?view=history` 在服务端分页前筛选终态，支持关键词与状态筛选；父子任务查询使用 `parentTaskId`。已读标记独立于成功或失败状态。结果的 `resume` 投递成功表示已加入来源会话处理队列，不代表模型已经读取或处理。

## 提问未回答兜底

`ask_user` 固定等待十分钟，不新增工具参数或数据库字段。超时依据已有 `createdAt` 计算，说明复用 `responseMessage`：已经过去10分钟未响应，用户可能正在忙，暂时无法回应。

- 非必答问题以已有 `skipped` 状态结束等待，明确这是未回答，并非用户作出决定；Agent 可继续原授权范围内的工作或跳过相关部分。
- 必答问题保持 `pending`，释放当前执行等待，原有求助卡片继续接受回答。后台任务保持条件等待；普通对话稍后回答时沿原 Thread、当前模式和权限继续。
- 普通对话的五分钟执行超时在等待用户期间暂停，结束等待后恢复剩余预算。工具审批保持独立。
- 后台扫描依据原创建时间处理超时；重启后保留必答问题，不重置期限。必答超时说明只写入一次，避免持续提醒。

## 数据库

标准迁移 `0002_proactive_work.sql` 扩展 `scheduled_tasks` 并创建 `proactive_suggestions`，`0017_recurring_schedules.sql` 增加周期字段。旧的 `is_triggered = 1` 记录迁移为完成态，避免升级后重放。结构变更进入统一迁移 journal，不增加启动时的临时建表逻辑。

## 调用链与维护入口

用户/Agent 授权的计划先持久化，到期由调度器领取，再经 BackgroundTaskService 创建实际任务；任务执行完成后由投递链保存通知、历史事件和队列唤醒。计划已派发、任务已完成、结果已投递与会话已消费是不同状态，不允许合并为一个“成功”。

任务领域入口为 `packages/backend/src/services/task/backgroundTaskService.ts`，会话唤醒入口为 `services/conversation/conversationQueueService.ts`。维护计划派发时保护领取租约、固定去重键、取消后的迟到结算与周期不重叠；排查任务完成但对话无结果时沿投递账本和队列继续定位，而不是再次派发同一任务。
