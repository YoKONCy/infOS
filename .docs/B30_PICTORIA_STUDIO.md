# Pictoria 画布工作室

本文描述当前画布编辑、助手与项目迁移的职责边界；供应商和任务执行仍由 Pictoria 自治 Host 管理。客户端入口为 `packages/apps/pictoria/client/src/components/CanvasStudio.vue`。

画布文档摘要使用 `@noble/hashes`，它同时属于 Pictoria 生产依赖与官方 Host 的显式发行外部依赖。`build-official-apps.mjs` 保留依赖边界检查，`collect-daemon-deps.mjs` 从 Pictoria 的生产依赖收集对应运行文件；新增 Host 依赖时须同时维护声明与发行边界。

常驻入口为右上角画布助手和项目工具菜单；图片编辑与编组放在选中节点后的原有浮动工具条。图像编辑器将蒙版方式与步骤选择收在弹窗参数栏中，统一使用 Pictoria 的图标、下拉组件和深浅色变量。助手打开时创作栏让出侧栏空间；多图任务和图片卡片显示候选数量，点击后展开可关闭的候选面板。空画布不显示小地图，小地图可手动收起。

## 图像编辑与候选结果

`ImageStudio.vue` 使用原素材像素建立编辑画布，笔刷支持橡皮擦、撤销与重做；显示缩放不改变蒙版坐标。裁剪支持拖框与数值坐标，网格切图最多 20 张，重采样提供平滑与最近邻方式。这些本机处理不调用模型，输出新 PNG 素材和历史来源连线，不覆盖原素材。单次图像处理限制约 6400 万像素，单素材上传上限沿用 20 MiB。

局部编辑只建立步骤草稿，用户补齐参数后主动执行。多图参考方式使用原图与蓝色区域标注图，由模型理解编辑范围，不保证硬蒙版约束。独立蒙版方式要求步骤声明单独的 `mask` 素材字段，用户选择透明区域可编辑或白色区域可编辑的约定；Pictoria 不推测供应商的蒙版协议。模型步骤和 API 适配仍通过现有 schema 与 `ServiceClient` 执行。

任务卡片 `outputIds` 始终保存素材 ID。输出素材的 `candidateGroupId` 指向任务卡片 ID，任务的 `primaryAssetId` 决定默认展示的候选。展开状态保存在项目中，已参与后续输入的素材不会因候选收起而隐藏。单张重试以当前同版本步骤与原输入创建新任务，将公开的数量参数设为 1，保留原结果；不支持单张数量参数的步骤须从创建栏显式重建。

## 助手、会话与增量提案

`src/canvasDocument.ts` 定义可审阅的增量协议，支持便签、移动、尺寸、命名、删除、编组、解组、选择、视口、连线及步骤草稿。协议没有脚本执行或提交生成任务操作。操作在文档副本上依次验证，客户端校验当前步骤的输入 schema 和连线素材类型后，才写入项目并建立撤销点。

`canvas.context.set/get/close` 保存按 owner、projectId、sessionId 隔离的实时上下文，包含画布、选择、视口、可用步骤、上下文序号和文档基准。上下文仅驻留内存，120 秒失效；定时心跳续期，不作为项目的持久数据。`canvas_read` 未指定项目时返回单一活动会话，或返回会话列表供调用者选择；多个窗口不会任意选取。返回的 JSON Schema 是 Agent 构造提案的权威字段契约。

`canvas.propose` 要求读取时的上下文序号，提案持久化为待确认记录，不直接修改项目。客户端确认时再次比较 `documentKey`；节点、标题或连线已变化则要求重新生成。仅选择与视口变化不改变文档基准。`canvas.proposal.resolve` 使用 revision 防止重复处理。用户仍需主动执行任何新建的生成草稿。

`CanvasProposalReview.vue` 将增量操作转换为可读列表，展示节点名称、分组成员、便签全文、草稿参数及连线对象；列表内部滚动，不截断用户确认所需内容。这里仅做展示，不改变提案协议或执行权限。

助手聊天使用 `canvas.conversation.get/save` 按项目持久化，更新带预期 revision。`canvas.assistant.prepare` 建立内置文本步骤：挂载模式走现有宿主模型授权，独立模式使用 Pictoria 自己的 OpenAI 兼容供应商和加密凭据引用。两者均通过现有 `task.submit` 执行引擎；助手任务使用 `assistant:<projectId>` 隔离项目 ID，文本回复不会被普通画布任务恢复逻辑当作素材输出。请求先持久化提交信息和幂等键，刷新后继续查询或恢复提交；原始无效回复保留，不尝试执行。

桌面挂载的请求先经过 `electron/main/services/pictoriaSurface.ts` 的显式操作白名单，再经宿主控制面转发到 Pictoria。画布助手的准备、上下文、会话和提案接口，以及 `project.rename`，须在桌面桥接层与应用 manifest 同时声明；不能仅增加客户端和后端实现。未知操作仍拒绝，错误包含具体操作名。桥接权限在 Electron 主进程注册时加载，仅刷新画布页面不会更新该权限表。

### 助手设置

助手头部显示当前模型，齿轮入口在同一侧栏切换设置视图。设置按模型、生成、上下文与创作偏好分组，常用字段两列排列；内容区滚动，保存栏固定。挂载模式默认沿用 infOS 主模型，不提供宿主模型卡片选择。独立运行仍使用 Pictoria 自己的供应商、模型与加密凭据。

`src/assistantSettings.ts` 是参数范围与默认值的权威定义。温度、Top P、输出上限和思考强度留空时不覆盖模型默认值；明确填写的零值保留。挂载调用通过步骤快照的 `implementation.options` 和可选 `HostPort.generate.options` 传递，宿主仅接收经过校验的调用参数，模型授权与主模型解析不变。协议、推理方言及模型能力仍由 infOS 模型配置决定。

独立助手继续走 OpenAI 兼容 Chat Completions，通过现有 `ServiceClient` 映射采样参数与输出长度。原生推理模型系列使用 `max_completion_tokens`，其他模型使用 `max_tokens`；此处的额度是供应商接口接收的总输出上限，不能推断为跨供应商一致的正文额度。思考强度按标准 `reasoning_effort` 传递，是否接受该字段取决于所配置模型，未实现其他供应商的私有推理协议。

`canvas.assistant.settings.get/save` 将设置存于所属 owner、projectId 的 `canvas-assistant-settings`，保存带预期 revision，冲突时不覆盖。会话与设置分开持久化，重置只恢复生成、上下文和偏好参数，保留已选供应商。设置不包含凭据，不随当前版本项目包迁移。

上下文范围支持全画布或选中项；选中分组包含成员，空选区明确报错，不退回整张画布。`services/assistantContext.ts` 保留完整文档基准，筛选请求视图并限制历史消息数。预算按序列化字符数计，当前最大 64000，与模型 token 窗口不是同一单位；超限先移除最早的整条历史，当前请求与范围内节点不截断，仍超限则拒绝发送。超时可设 30 至 600 秒，默认 600 秒，独立接口与宿主调用均实际应用。

创作偏好附加在固定提案协议后，只影响内容，不增加操作权限。每次提交冻结设置、上下文与历史，生成参数和偏好变化会创建新的助手步骤快照，不改写已接受任务；恢复请求仍使用原步骤版本和原始输入。内部助手快照不进入步骤与服务菜单，也不挤占用户定义的列表额度。看图开关不随设置保存，仍由每次会话的显式勾选控制。

上下文默认只有节点结构、文本及资源标识，不发送图片像素。用户勾选“分析所选图片”后，本次请求附带明确选中的 PNG、JPEG 或 WebP，最多四张、总量 20 MiB；不发送画布上其余图片。`imageBindings` 顺序对应实际多模态图片，提交记录保存素材引用以便刷新后恢复相同请求。普通上下文读取仍只返回结构。

挂载模式沿用已授权模型桥接的图片输入，模型须启用视觉；独立模式通过声明式 `openai_content` 映射，把 `prompt` 和 `images` 编码为 OpenAI 兼容多模态消息。像素只在请求发送边界从所属素材读取，凭据仍由供应商加密存储管理。独立视觉接口返回错误时不保留可能回显图片的错误正文。

`update_draft` 合并已有草稿输入，保持未指定字段；按提案顺序移除被改写字段当时已有的输入连线，之后显式建立的新连线仍保留。确认时按步骤 schema 校验，提案仍不提交生成任务。分析文字可通过 `note` 写入便签，或通过 `draft` 建立新草稿。

## 视频接续与片段序列

`VideoContinuationStudio.vue` 复用图像工作室的浮层、预览区、参数栏与深浅色变量。选中视频的“接着生成”入口打开接续创作；浏览器原生解码读取末尾候选画面，也可从播放器当前位置提取 JPEG。时间是浏览器定位时间，不假定固定帧率；不宣称实现离线逐帧精确剪辑。

挂载模式的视频预览按已有素材总上限支持 100 MiB；图片和其他素材仍沿用 20 MiB 的画布预览上限。该调整不放宽助手图片数量或总量限制。前端继续使用已有预览缓存与媒体引用租约，当前源视频和正在播放的片段不会在使用中被缓存淘汰。

步骤的输入 schema 用 `x-pictoria-video: { startFrameField: "images" }` 明确起始帧字段，支持单素材对象或素材数组的第一项。已知内置图生视频适配提供该声明；自定义步骤须按真实 API 配置。普通多图参考不会自动获得接续入口能力，也不会调用未声明的原片延长接口。

接续草稿持久化 `continuation`：源素材引用、源节点与名称、源定位时间、原片时长和抽取画面引用。执行与输出沿用这份来源，不因源任务出现其他结果而替换。新起始帧单独绑定，旧首尾帧不自动继承；人物与风格等辅助参考只在对应字段可用、且用户选择继承时复用，同一字段中未标注或仅标注构图的图片不混入下一段。修改接续起始帧后须重新建立接续关系，避免来源记录与真实输入不符。

“片段序列”追溯固定素材的祖先、展示接续任务与各结果分支；连播在下一段记录的源定位点切换，原片文件不裁切。可从生成结果继续建立下一段。该预览依赖浏览器播放调度，不提供无缝音频、帧精确合成或成片导出保证。抽帧、选帧、草稿和执行不依赖 Agent。实现入口为 `services/videoContinuation.ts`；任务仍通过现有 `createRun` / Host 执行。

## 参考图用途

创建栏和草稿卡片按步骤、字段和素材 ID 保存 `referenceUses`，不把用途字段塞进供应商的素材对象。`creativeInputs.ts` 在提交时按实际引用位置为兼容文本字段附加用途说明；不排序图片、不重新调用模型，也不修改用户原文。没有显式用途时按原输入传递。没有可接收说明的文本字段时不开放用途编辑。

任务卡片保留实际发送输入与用途记录；原草稿保留原文及独立标注，重试不会重复追加说明。用途提示属于模型指令，不等于供应商提供的强制控制能力。项目包递归携带标注、接续源和抽取画面引用，导入时沿用统一素材 ID 重映射。

## 编组、视口与项目包

分组是独立 `group` 节点，成员通过 `groupId` 引用，坐标始终为画布绝对坐标。整组拖动递归移动成员；解组保留坐标并恢复上级组关系；复制组会重映射成员关系。删除分组框不删除成员。项目 `viewport` 保存平移与缩放，加载、撤销和重做恢复对应视口，小地图只修改同一视口。

`client/src/services/projectPackage.ts` 定义 ZIP 格式 `pictoria.project`、版本 1：`project.json` 为清单，`assets/<序号>` 存原始字节。递归收集画布与创建栏的素材引用，包含输入顺序、主图和输出素材；跳过执行请求标识。每个素材记录长度与 SHA-256，摘要使用兼容普通 HTTP 浏览器的本地算法。

导出不包含运行中的任务或凭据。导入限制压缩包与声明解压总量各 256 MiB、2000 个节点与素材、8000 条边；拒绝异常路径、重复条目、缺失或篡改资源及循环分组。先完整校验，再显示确认，确认后上传素材并重映射全部资源 ID，最后一次保存新项目。失败不替换原项目；上传中断时已经写入的素材可留在资源库中。运行记录不迁移执行权，历史结果保留，API 草稿须使用当前环境的有效步骤配置。

实现入口：`src/canvasStudio.ts` 管理上下文与助手定义，`useCanvasAssistant.ts` 处理持久会话与确认应用，`CanvasMinimap.vue` 负责导航，`useCanvas.ts` 是项目、撤销与运行结果的持久状态来源。

## 可编辑文档与默认文案

项目、工作流、备注和字段 Schema 属于可写文档；不能将编辑器会修改的 `title`、`label`、`usageDescription` 定义成仅有 getter 的属性。默认备注、示例和步骤字段在创建时通过 i18n 生成普通文本，之后按用户内容保存与编辑。菜单选项等纯界面标签仍动态翻译；空画布标题通过成对的 getter／setter 保持默认名称的语言响应，同时支持项目加载、草稿恢复、重命名及撤销重做。
