# Thread 交互模式与工具准入

## 持久化与切换

- `threads.interaction_mode` 保存交互模式（`chat` / `work` / `minimal`），独立于 Channel、用途和自动执行设置。
- 新普通桌面 Thread 默认聊天模式；后台任务和应用内部 Thread 使用工作模式。
- 标准迁移 `0007_thread_interaction_mode` 将已有 Thread 标记为工作模式，保留原有能力。
- 对话栏切换通过 `PUT /api/chat/threads/:id/interaction-mode` 保存；普通桌面会话空闲时才能切换。
- 切换不新建会话、不清空历史、不改写 `disabled_tools_json`，也不改变已派发任务的独立 Thread。

## 会话设置与新会话继承

普通桌面 Thread 上与对话相关的会话设置有：`interaction_mode`、`execution_mode`、`model_config_id`、`reasoning_effort`。

- `ThreadService.createThread` 创建普通桌面对话（`channel=desktop`、`purpose=conversation`）时，读取同一角色最近活跃的普通对话并复制模式、模型与思考强度；后台任务、群聊、应用内部 Thread 与其他角色的会话不参与。活跃顺序使用迁移 `0026_thread_activity_sequence` 添加的 `activity_seq`：数据库触发器在创建、发消息（更新计数）、改设置、改标题及其他原有 `updated_at` 写入时，从单行 `thread_activity_clock` 分配递增序号，和业务写入处于同一事务，同秒操作及并发连接不依赖时间精度。`updated_at` 仍用于展示；升级只按原有时间与创建顺序为旧记录初始化序号，不能还原升级前同秒操作的先后。
- 执行权限只继承 `manual` 与 `auto`；上一会话为 `auto_approve` 或 `full` 时新会话回落为 `manual`，避免在用户不知情时沿用放开的权限。运行时调试按会话单独开启，不继承。没有历史对话时使用列默认值。
- 继承在服务端完成，桌面、工作区、桌宠等所有经 `POST /api/chat/threads` 或服务端内部入口创建的普通对话一致生效。识图方式与语音输入方式是输入栏的本地选择，不随 Thread 保存，也不继承。

## 能力门控

模式是 Channel / 角色能力之上的减法层。工具定义、能力描述、Skills 指引和实际执行使用同一模式策略。Skills 选择独立保存在会话中，极简模式保留选择但暂停指引装配；接口和权限规则见[会话 Skills](M02_CAPABILITY_GATE.md#32-会话-skills)。

极简模式的主会话工具为 `conversation`、`update_flow_state` 和 `finish_task`，侧会话工具为 `update_flow_state` 和 `finish_task`。`MINIMAL_TOOLS` 定义模式上限，编译器、工具菜单和执行器再依据真实 Thread 类型限制连续交流协议。主线使用 `conversation` 发布消息、登记等待和处理待回应事项，SideThread 沿用普通回复，也可通过 `finish_task.reply` 交付。极简模式首个模型请求即提供并允许调用 `finish_task`。记事本主文件继续按上下文规则提供已有内容，文件维护和主动查询通过聊天或工作模式的获准工具完成。

聊天允许列表维护于 `packages/backend/src/tools/interactionMode.ts`：

- 对话状态、事件查询、事实查询与主线事实修改、文档知识库检索。
- 配置完成的联网搜索与网页读取；天气由状态上下文注入，不提供专用查询工具。
- 提醒、一次性跟进和待采纳建议。
- 文件读取、目录与文本搜索、代码搜索、写入和编辑。
- `manage_task` 提供任务查询、派发与控制；各操作仍受调用身份、任务所有权和执行模式约束。

文件删除、终端、桌面操作、工作控制工具与高级工具展开只在相应工作范围开放。`run_script` 在聊天允许列表中，但脚本内调用继续受当前模式与权限约束，不能借脚本扩大能力。`document`、`runtime_debug` 和 runtime-scoped 工具仅工作模式可用。
模式门控不继承“系统协议工具始终可用”的豁免。执行器从 Thread 读取权威策略，脚本嵌套调用仍受会话限制。
审批、路径范围、设备能力和后台任务受限作用域继续独立生效。

## 扩展

扩展配置保存 `chatEnabled`，默认 `false`；官方扩展配置页提供“聊天模式可用”开关。
注册工具时通过 `ToolRegistry.register(..., { chatEnabled })` 声明，聊天允许列表不包含扩展名称。
扩展仍需启用、配置完整并满足角色能力和会话逐项设置；修改聊天开关不自动授予这些条件。

## 前端与提示词

- 输入栏最左侧的“模式 · 模型”文字入口打开会话设置面板（`SessionSettingsPanel.vue`），依次提供模型、模型思考、会话模式（工作模式下展开调试开关）、执行权限及识图／语音。执行权限只在该面板调整，会话工具弹层只保留工具列表；放开到自动审批或完整权限需在面板内确认，降低立即生效，放开后入口的模式文字以警示色提示。面板与入口使用像素字体和主题变量，适配深浅主题与紧凑布局（窄宽度只显示模式）。极简模式提示列出心流、完成任务和主会话发言，工具菜单按主侧类型显示有效状态。
- 工具接口分别返回 `enabled`、`userEnabled`、`modeAllowed`，区分有效状态、手动设置和模式限制。
- 工具计数只计算当前模式可用范围；受模式限制的项目标记“模式未开放”。
- 能力说明注入 `components/abilities/interaction_mode.md`，用户名使用既有 `owner_name`；关闭工具的完整定义不注入模型。
- 模式提示词只解释当前可用范围；授权以执行器校验为准，不能依赖模型遵守文案。

## 会话分支

桌面对话和工作区协作栏中，SideThread 的已保存回复提供「从此处新建会话」。`POST /api/chat/threads/:id/fork` 接收回复的 `messageId`，复制截至该回复所属完整轮次的尚存消息，目标为新的 SideThread。主线通过服务端生命周期规则保护，支持清空重置。详见 [主侧会话](./B26_MAIN_SIDE_THREADS.md)。

`services/thread/threadForkService.ts` 在提交时读取来源的当前设置，继承模型与推理强度、交互与执行模式、工具开关、Skills 和上下文策略。当前心流、工作上下文清理边界、公开行动计划及酒馆局部变量成为新会话的独立基线，检查点决定聊天历史的截止位置。角色共享状态、长记忆、知识、工作区文件及全局配置按既有权威源读取。计划步骤保存当前投影值，任务、调度、审批、执行进程和工具运行时归原会话。

消息与轮次生成新 ID，保留正文、原始转写、修订号、时间和历史工具记录。工作轨迹中的 Thread、轮次、消息锚点及附件引用同步重映射。`metadataJson.forkOrigin` 保存来源 Thread、消息和检查点。SideThread 消息的 `scorerStatus` 为 `skipped`，后续新消息沿用侧线的事件只读、记事本维护与事实修改限制。

附件字节先复制到独立存储键并核对大小与 SHA256，记录在会话事务内绑定到新消息。局部变量通过 `SillyTavernVariableStore.forkThread` 与变量提交串行，再同新会话、消息、附件绑定及状态一次提交。提交前复查来源历史与附件，前缀被修改或撤回时拒绝本次复制并清理新附件。来源在检查点之后继续追加消息，可照常进行。事务或捕获失败时保留原数据，清理本次尚未绑定的附件副本。

旧会话表达状态的兼容事件按有效历史复制为本地资料，新角色状态统一读取共享服务。行动计划建立独立基线变更记录，复制历史的撤回保留继承的当前计划。分支从新发生的轮次建立文件变更记录，工作区原有文件与来源的恢复历史保留原归属。

## 修改时的约束

`packages/backend/src/tools/interactionMode.ts` 是模式准入入口，注册元数据决定扩展是否可在聊天使用。修改模式时同时检查工具菜单、能力说明和实际执行，避免“看得见但调用不了”或隐藏工具仍可被脚本调用。交互模式决定工具集合；[B19 执行模式](./B19_THREAD_EXECUTION_MODES.md) 决定如何审批，两者独立。
