# NIT 编排引擎

> **核心定位**：将 NIT 作为标准的 Function Calling 工具。
> **最后更新**：2026-10-17

---

## 1. 架构变更

NIT 通过 **`run_script`** 工具进入模型调用链。词法、语法与 AST 执行均位于 `packages/backend/src/nit/`，是仓库内 TypeScript 实现，不是 Rust / N-API 模块。

- **LLM 调用**：通过标准 FC 语法调用 `run_script(code="...")`。
- **执行**：后端 `NitRuntime` 执行脚本，脚本内部调用的工具递归走 `ToolRegistry`。
- **优势**：消除 LLM 的协议竞争认知，零 system prompt 开销。

---

## 2. 语法子集

NIT 提供轻量级沙箱语法：

- **基础**：赋值、属性访问 (`obj.field`)、字符串拼接。
- **控制流**：`if-else`, `for-in`, `try-catch`, `return`。
- **并发**：`parallel { ... }` 块实现多工具并发。
- **限制**：禁止函数定义、禁止网络/文件直接 IO、禁止递归。

---

## 3. 使用场景 (Agent DSL)

适用于参数与分支已明确、可以按工具真实结果推进的多步操作。语法与执行入口分别为 `nit/parser.ts`、`nit/runtime.ts` 和 `tools/runScript/`；精确参数以该工具 manifest 为准。需要语义判断时将结果返回模型，不能用脚本臆测内容结论。模型只能通过注入的工具执行器调用当前获准工具，不获得直接网络/文件 IO。

---

## 4. 工具结果与跨轮上下文

- 内部工具输出保留脚本计算所需业务值；文件 diff 移到独立展示结果，不把任意用户 JSON 中的同名字段视为展示数据。
- 内部调用与直接调用使用同一观察回调，真实路径、版本和读取来源能随 Thread 保存。模型看到的内部调用列表不再用 500 字符残片代替结果。
- 显式 return 和隐式最后表达式都受外层统一 128,000 字符观察预算约束。超限通过完整外壳与短期结果引用继续读取，不重复执行已有副作用。
- 已执行脚本可在合法工具对边界退出旧的大参数；混合脚本的业务结果仍保留。原生签名、失败和未完成调用不会被随意改写。
- 这些规则不改变脚本取消、超时和内部终端回收责任。

## 5. 退化生成与工具循环保护

- 统一模型门面按单次请求分别检查正文、原生思考、工具名称和每个调用的参数流；窗口有界，检测不依赖网络分片。仅认逐字相同的连续周期，不用语义相似度或低熵直接停任务。
- 默认正文与思考需连续重复至少 8192 字符且满 16 个周期；代码块和结构化排版提高到 32768 字符、32 个周期；工具参数提高到 65536 字符、64 个周期。纯结构字符、数字和参数内的原始媒体编码不作为复读停止依据。工具名称采用 4096 字符的独立门槛。
- 检出后取消当前上游请求，丢弃未完成工具参数，保存已显示进度与错误原因；不会以网络重试或模型回退重新播放异常生成。非流式响应只能在接收完成后、执行工具之前检查，不能提前停止远端生成。
- 每次 ReAct 独立持有工具循环窗口，直接调用和 NIT 子工具共享。相同参数与相同失败结果连续循环 6 次，或稳定只读结果连续循环 12 次后，先拦截一次并给模型纠偏机会；继续原样调用才切断并取消关联工具。支持长度为 1 至 4 的动作周期。
- 等待、终端轮询、截图、浏览器观察和社交发送等动态操作不按相同结果计数。目标、参数、结果或文件版本变化会打断原循环证据；短期读取引用的更新不当作文件进展。成功修改等其他操作清除读取循环窗口。普通工具的不同失败、连续错误上限仍遵循原有策略。
- 有子工具的 NIT 脚本只记录子工具；无子工具的纯计算脚本才比较脚本本身。社交业务编排同样检查能力调用，并在继续编排或请求模型之前检查取消状态。
- 误伤优先级高于覆盖率，因此不推断语义上的原地打转，也不限制正常长任务总轮数。维护回归须同时保护异常检测、取消传播与正常长任务不被误判；执行结果以对应检查记录为准。
