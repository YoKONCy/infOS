# infOS 前端视觉与交互设计规范

> **文档编号**：S06
> **设计主题**：AIOS Agent Workstation — Arc Modern × Pixel Moe
> **适用范围**：MainView 综合面板、Dashboard 功能组件、Chat、Stronghold、Workspace 及后续 Web 节点界面
> **不适用范围**：LauncherView、Pet3DView 的窗口形态与特殊交互
> **状态**：设计基线（后续实现必须优先遵循）

---

## 1. 设计定位

infOS 的前端是一个具有角色人格、工具能力、多节点接入与长期运行能力的 **AIOS 全能 Agent 工作站**。

新界面的目标不是推翻现有 Dashboard 的萌系像素风，而是保留其优秀的品牌资产，并使用现代桌面软件的空间组织、信息层级、排版、动画和悬浮交互重新构建视觉系统。

### 1.1 核心公式

```text
Arc 式现代空间结构
+ Dashboard 现有像素与萌系品牌资产
+ 专业工作站的信息密度与可读性
= infOS AIOS 视觉语言
```

### 1.2 设计关键词

- 现代、轻盈、克制
- 清晰、可靠、高效
- 二次元但不幼稚
- 像素化但不复古堆砌
- 有空间层级而非平面堆卡片
- 有人格温度但不干扰工作

### 1.3 基本原则

1. **现代负责骨架，像素负责识别度**：布局、层级、排版和基础组件采用现代设计；像素图标、选中态、按压反馈和少量装饰承担品牌表达。
2. **内容优先**：装饰不能影响对话、日志、记忆、配置和终端内容的阅读。
3. **像素元素是工艺细节，不是全局材质**：避免每个容器都使用粗像素边框。
4. **萌系色彩作为强调，不作为大面积底色**：粉、天蓝、紫用于品牌、状态和交互焦点，大面积背景使用中性色。
5. **层级通过空间表达**：优先使用留白、背景层差、细边框、阴影、模糊和动效，而不是堆叠粗边框。
6. **功能密度可高，视觉噪音必须低**：工作站可以容纳复杂信息，但每一屏必须有明确焦点。
7. **深浅主题语义一致**：主题切换只改变视觉令牌，不改变组件层级和信息含义。

## 2. 现有设计资产的保留策略

现有 Dashboard 中以下设计应尽量保留并升级，而不是删除。

### 2.1 必须保留

- `PixelIcon` 像素图标系统。
- Zpix 像素字体作为品牌和标签字体。
- Sky、Pink、Purple、Amber、Emerald 等已有色阶及语义关系。
- 按钮的像素按压反馈。
- `steps()` 跳帧动画与弹性曲线作为品牌动效。
- 统计卡片中的大数字、英文小注、状态色和轻量装饰。
- 日志、记忆、模型配置中已经成熟的颜色编码。
- 终端的独立暗色视觉与 CRT 细节。
- 猫爪、sparkle、thought 等轻量二次元装饰。
- 总览页的环境光和粒子氛围。

### 2.2 降级为特殊状态使用

- `.pixel-border-moe`：从默认容器边框降级为选中态、关键状态和品牌高亮。
- 大型像素硬阴影：仅用于主操作按钮、确认操作、小型强调控件。
- 粗像素卡片：仅用于特殊功能卡、空状态和需要游戏化反馈的区域。
- 像素字体：不再用于长正文、表单输入内容和密集数据。
- 多彩渐变：仅用于图标底、数据强调和氛围光，不作为每张卡片的背景。

**对话与据点的氛围修正**：对话和据点是角色工作台，允许主轴氛围（环境光、极浅角色纹理、轮廓光轨），但正文气泡不能噪。不得把一体化面板变成完全没有个性的空白 SaaS 聊天页。

### 2.3 应移除或严格限制

- 同一层级同时出现粗边框、强阴影、发光、渐变和粒子。
- 所有卡片都使用像素边框。
- 大面积高饱和粉蓝紫背景。
- 没有信息意义的持续旋转、弹跳和闪烁。
- 使用过多 `font-black`、全大写英文和像素字体造成视觉喊叫。
- 内容区嵌套三层以上同风格卡片。

## 3. 空间与层级系统

### 3.1 页面层级

| 层级 | 名称     | 典型内容                      | 视觉方式                     |
| ---- | -------- | ----------------------------- | ---------------------------- |
| L0   | 环境层   | 页面背景、主题底色            | 中性色、轻微纹理，不承载交互 |
| L1   | 工作区层 | 侧边栏、主内容区              | 背景明度差或 1px 分隔线      |
| L2   | 内容层   | 卡片、列表、聊天、配置组      | 细边框、低阴影、小圆角       |
| L3   | 浮动层   | 下拉菜单、Tooltip、上下文菜单 | 中阴影、较高不透明度         |
| L4   | 二级页面 | 详情、编辑、调试查看器        | 遮罩 + 右侧悬浮面板          |
| L5   | 阻断层   | 危险确认、强制决策            | 居中 Modal + 强遮罩          |
| L6   | 通知层   | Toast、全局状态提示           | 页面顶层，不阻断操作         |

### 3.2 主布局

- 主导航与内容区使用 Arc 式空间关系：通过背景差、细线与柔和阴影分隔，不使用粗黑描边。
- 导航展开宽度建议 `232px–256px`；收起宽度建议 `60px–72px`。
- 主内容区最小安全内边距：桌面 `24px`，宽屏 `32px`，窄屏 `16px`。
- 信息页建议设置 `1280px–1440px` 的内容最大宽度；聊天、终端、日志可占满可用空间。
- 主导航、标题栏和状态栏属于稳定框架；功能内容切换时不应重新布局或闪烁。

### 3.3 遮罩与二级悬浮页面

普通详情和编辑操作优先使用右侧 Slide-over，而不是居中弹窗。

```css
--overlay-backdrop: rgba(15, 23, 42, 0.38);
--overlay-backdrop-dark: rgba(0, 0, 0, 0.58);
--overlay-blur: 8px;
--overlay-panel-width-sm: 420px;
--overlay-panel-width-md: 520px;
--overlay-panel-width-lg: 720px;
```

规范：

- 遮罩应降低背景注意力，但保留当前工作上下文。
- 面板从右侧滑入，桌面端高度占满工作区。
- 面板左侧使用柔和投影，不使用粗像素描边。
- 面板顶部固定标题、上下文信息和关闭按钮。
- 详情、编辑、调试可使用 Slide-over；危险确认仍使用居中 Modal。
- 点击遮罩和按 `Esc` 可关闭非阻断面板。
- 面板打开时应锁定背景滚动，并正确管理焦点。

## 4. 颜色系统

### 4.1 颜色使用原则

1. 组件优先使用语义令牌，不直接引用具体色阶。
2. Sky 表示系统能力与默认交互；Pink 表示 Pero 品牌与人格强调；Purple 表示智能、记忆和推理；Emerald 表示健康与成功；Amber 表示提醒；Red 表示危险。
3. 品牌色在单个视图中的视觉占比建议不超过 15%。
4. 大面积背景必须使用中性色；饱和色仅用于小面积强调。
5. 文本与背景必须满足基本可读性，禁止浅色文字叠加浅色渐变。

### 4.4 与现有令牌的关系

- 保留 `--color-sky-*`、`--color-pink-*`、`--color-moe-*`，用于像素组件和品牌细节。
- 新增 `--ui-*` 令牌用于现代框架、卡片、文字、边框和主题切换。
- 迁移期允许新旧令牌共存，但新 MainView 和新组件必须优先使用 `--ui-*`。
- 禁止在业务组件中重复定义同义颜色。

### 4.5 自定义壁纸四层光学分层

启用应用背景（`[data-app-background='active']`，见 `AppWallpaper.vue`、`useAppBackground.ts`、`app-background.css`、`light-theme.css`）时，界面按四层合成，避免浅色发脏与文字透底：

1. **原画层（Artwork Layer）**：`blur: 0` 时保持原画锐利，不在浅色模式下强制追加模糊；`cover` 模式下支持在设置页实时预览框内直接拖拽调整 `positionX / positionY` 焦点。
2. **自适应光学垫底层（Adaptive Optical Scrim + Veil）**：壁纸加载完成时通过 `24×24` 离屏 `<canvas>` 单次采样亮度与明暗跨度，输出 `data-wallpaper-tone="dark|balanced|bright"`。暗图在浅色模式下自动垫入柔雾提亮层、亮图在深色模式下自动压暗，再叠加 `color-mix(in oklab, ...)` 主题遮罩。
3. **高饱和晶透壳层（Frosted Shell & Anti-Ghosting Overlays）**：标题栏、导航、侧栏等固定壳层使用 `backdrop-filter: blur(var(--app-material-blur)) saturate(var(--app-material-saturate, 172%))` 防止壁纸透过半透明白底泛灰；二级浮层（折叠面板、Popover、Drawer、Dialog、右键菜单）提升至 `95%–97%` 实度并配合毛玻璃，防止穿透底层文字。
4. **阅读卡片层（Dual Crystal Border Cards）**：消息列表内气泡不使用逐项 `backdrop-filter` 以保证滚动帧率，改用高实度阅读填充配合外层 `1px` 深色轮廓与内层 `inset 0 1px 0` 纯白高光（`--app-crystal-border` / `--app-crystal-shadow`），并根据 `data-wallpaper-tone` 微调描边强度。

## 5. 阴影与光照

阴影必须表达层级，不应只是装饰。

```css
:root {
  --ui-shadow-xs: 0 1px 2px rgba(15, 23, 42, 0.04);
  --ui-shadow-sm: 0 2px 8px rgba(15, 23, 42, 0.055);
  --ui-shadow-md: 0 8px 24px rgba(15, 23, 42, 0.085);
  --ui-shadow-lg: 0 18px 48px rgba(15, 23, 42, 0.14);
  --ui-shadow-panel: -12px 0 40px rgba(15, 23, 42, 0.16);
  --ui-glow-pink: 0 0 24px rgba(236, 72, 153, 0.16);
  --ui-glow-sky: 0 0 24px rgba(14, 165, 233, 0.15);
  --ui-glow-purple: 0 0 24px rgba(139, 92, 246, 0.16);
}
```

| 层级     | 阴影       | 场景                           |
| -------- | ---------- | ------------------------------ |
| 平面     | 无或 `xs`  | 普通列表行、表单组             |
| 卡片     | `sm`       | 总览卡片、配置分组             |
| 悬浮控件 | `md`       | 下拉菜单、上下文菜单、Tooltip  |
| 二级页面 | `lg/panel` | Slide-over、调试详情           |
| 品牌高亮 | glow       | 选中 Agent、关键能力、当前状态 |

规则：

- 默认卡片不使用大范围彩色发光。
- Glow 只在选中态、运行态或关键品牌组件出现。
- 同一元素不得同时使用大软阴影和强像素硬阴影。
- 深色模式下阴影透明度可提高，边框仍需保留以明确边界。

## 6. 边框、圆角与像素轮廓

### 6.1 现代边框

```css
--ui-border-width: 1px;
--ui-radius-xs: 4px;
--ui-radius-sm: 7px;
--ui-radius-md: 10px;
--ui-radius-lg: 14px;
--ui-radius-xl: 18px;
```

- 输入框、按钮：`7px–10px`。
- 普通卡片：`10px–14px`。
- 大型悬浮面板：左侧 `16px–18px`，贴边侧保持 0。
- 标签、状态胶囊：可使用全圆角，但不得滥用。
- 终端、代码区域可使用 `7px–10px` 小圆角。

### 6.2 像素边框使用条件

像素边框仅用于：

- 当前选中的 Agent 或设施。
- 当前激活的关键模式。
- 主按钮按下态。
- 具有品牌意义的头像框、徽章、空状态插画。
- 少量需要复古游戏反馈的控件。

禁止用于：

- 普通页面外框。
- 所有设置表单容器。
- 长列表的每一行。
- Slide-over 主面板。
- 遮罩和大面积背景。

现有多重 `box-shadow` 像素边框应继续保留，不改成平滑描边；但通过减少出现频率获得高级感。

### 6.3 选中态建议

```css
.is-pixel-selected {
  background: var(--ui-bg-active);
  box-shadow:
    -2px 0 0 var(--color-moe-cocoa),
    2px 0 0 var(--color-moe-cocoa),
    0 -2px 0 var(--color-moe-cocoa),
    0 2px 0 var(--color-moe-cocoa),
    var(--ui-glow-pink);
}
```

深色主题不应使用接近纯黑的可可色描边，应通过主题令牌切换为较亮的粉灰或紫灰轮廓。

## 7. 字体与排版

### 7.1 字体分工

```css
--ui-font-sans: Inter, 'PingFang SC', 'Microsoft YaHei', 'Segoe UI', system-ui, sans-serif;
--ui-font-pixel: 'Zpix', 'DotGothic16', monospace;
--ui-font-mono: 'JetBrains Mono', 'Cascadia Code', Consolas, monospace;
```

| 字体  | 使用场景                                 |
| ----- | ---------------------------------------- |
| Sans  | 正文、表单、列表、说明、长文本           |
| Pixel | Logo、模块标题、短标签、状态码、关键按钮 |
| Mono  | 终端、代码、ID、时间戳、技术参数         |

### 7.2 禁止事项

- 像素字体不得用于超过两行的正文。
- 长中文标题不得使用过小的像素字体。
- 不得用全大写英文替代中文主标签；英文只作为辅助说明。
- 不得全页面使用 `font-black`。

### 7.3 字号与字重

| 名称        | 字号/行高 | 字重    | 用途                     |
| ----------- | --------- | ------- | ------------------------ |
| Display     | 28/36     | 700     | 页面主标题、关键数字     |
| Title       | 20/28     | 650–700 | 模块标题                 |
| Heading     | 16/24     | 600–700 | 卡片标题                 |
| Body        | 14/22     | 400–500 | 默认正文                 |
| Compact     | 13/20     | 400–600 | 密集列表和侧边栏         |
| Caption     | 11/16     | 500–700 | 元信息、时间、状态       |
| Pixel Label | 10–12/16  | 700–800 | 像素标签、按钮、英文小注 |

### 7.4 中英文标签

推荐：

```text
核心记忆
MEMORY CORE
```

- 中文为主信息，英文为辅助语义。
- 英文使用较小字号、较大字距和较低对比度。
- 同一区域应保持一致，不要有的组件中英双语、有的只写英文。

## 8. 间距与栅格

采用 4px 基础网格：

```css
--ui-space-1: 4px;
--ui-space-2: 8px;
--ui-space-3: 12px;
--ui-space-4: 16px;
--ui-space-5: 20px;
--ui-space-6: 24px;
--ui-space-8: 32px;
--ui-space-10: 40px;
--ui-space-12: 48px;
```

规则：

- 图标与文字：8px 或 12px。
- 表单标签与控件：6px–8px。
- 同组控件：12px–16px。
- 卡片内边距：普通 20px，密集 16px，大型 24px。
- 卡片间距：16px–24px。
- 页面区块间距：32px–40px。
- 侧边栏项目高度：38px–44px。
- 不使用没有体系的 17px、19px、27px 等随机值，特殊视觉对齐除外。

### 8.1 响应式断点建议

| 断点          | 行为                                    |
| ------------- | --------------------------------------- |
| `>= 1440px`   | 宽屏工作站，允许三栏和大尺寸 Slide-over |
| `1024–1439px` | 标准桌面，导航可自动收起                |
| `768–1023px`  | 紧凑模式，二级侧栏改为抽屉              |
| `< 768px`     | 单栏布局，主导航改为覆盖层或底部入口    |

## 9. 表面与玻璃拟态

玻璃拟态只用于需要表达浮动和环境融合的组件。

```css
.ui-glass {
  background: color-mix(in srgb, var(--ui-bg-elevated) 86%, transparent);
  border: 1px solid var(--ui-border-subtle);
  backdrop-filter: blur(16px) saturate(1.08);
}
```

允许场景：

- MainView 侧边栏。
- 顶部标题栏。
- 浮动工具条。
- 下拉菜单和上下文菜单。
- Slide-over 头部。

不建议场景：

- 长文本内容背景。
- 每一张普通卡片。
- 终端正文。
- 多层嵌套容器。

玻璃层后方应有稳定背景，禁止因透明造成文字对比不足。

### 9.1 Texture材质系统

Texture不是规则网格、几条重复直线或单层noise。需要表达磨砂、纸张、织物、矿物、木材等触感时，每个主表面至少包含四层：

```text
基础层     中性基础色 +低频、不均匀色差
颗粒层     固定seed的非规则微颗粒/磨砂噪声
结构层     与材质相符的方向性结构，例如纵横纤维、矿物斑驳或木质导管
光照层     内嵌明暗边、局部压痕、磨损和细微反射差
辅助层     可选的断线坐标、像素划痕或网格；权重必须低于前四层
```

实现要求：

-优先使用多层CSS渐变与确定性内嵌SVG`feTurbulence`，必须固定`seed`，禁止刷新闪烁；-相邻层级不得复用同一Texture。托底与内容工作面必须在seed、尺度、方向、色温和混合模式上可辨；-规则点阵、直线网格和扫描线只允许作为低透明辅助层，不得承担磨砂、纸张或织物质感主体；-纹理必须位于背景层并保持`pointer-events:none`，不能覆盖文字、Selection和Caret；-纹理对比默认2–5%，明确的材质工作站可提高到4–7%，但正文区域必须降低高频噪声；-浅色材质不得退化为纯白卡片；暗色材质不得退化为黑色玻璃卡片；-需要长时间阅读的表面，必须检查中文小字号、输入光标和选区在纹理上的稳定性。

禁止形态：

```text
单一repeating-linear-gradient冒充纸张
规则圆点阵列冒充磨砂
全页面复用同一张noise
高对比随机斑点穿过正文
纯装饰纹理导致无法分辨L0环境层与L1工作区层
```

## 10. 动效规范

### 10.1 时间与曲线

```css
--ui-duration-instant: 90ms;
--ui-duration-fast: 150ms;
--ui-duration-normal: 220ms;
--ui-duration-panel: 320ms;
--ui-ease-standard: cubic-bezier(0.2, 0, 0, 1);
--ui-ease-emphasized: cubic-bezier(0.32, 0.72, 0, 1);
--ui-ease-pixel: steps(3);
--ui-ease-bouncy: cubic-bezier(0.34, 1.56, 0.64, 1);
```

### 10.2 动效分工

| 动效       | 规范                                    |
| ---------- | --------------------------------------- |
| hover      | 150ms，颜色/阴影/1px 位移，避免大幅旋转 |
| 按压       | 90ms，保留现有像素按钮下沉反馈          |
| Tab 切换   | 180–220ms，淡入 + 4px 位移              |
| 导航收起   | 220ms，宽度与文本透明度协调变化         |
| Slide-over | 320ms，从右滑入，使用 emphasized 曲线   |
| Toast      | 200ms，淡入并轻微上移                   |
| 像素动画   | 使用 `steps()`，仅品牌状态或空状态      |

### 10.3 装饰动画限制

- 粒子和环境光仅保留在总览页、引导页和空状态。
- 同一区域最多一个持续动画焦点。
- 用户阅读日志、终端、代码、配置时不显示粒子。
- `prefers-reduced-motion: reduce` 下必须关闭粒子、弹跳和大幅位移。
- Loading 动画可保留像素步进特色。

## 11. 核心组件规范

### 11.1 卡片

默认卡片：

```css
.ui-card {
  background: var(--ui-bg-surface);
  border: 1px solid var(--ui-border-subtle);
  border-radius: var(--ui-radius-lg);
  box-shadow: var(--ui-shadow-xs);
  transition:
    border-color var(--ui-duration-fast) var(--ui-ease-standard),
    box-shadow var(--ui-duration-normal) var(--ui-ease-standard),
    transform var(--ui-duration-normal) var(--ui-ease-standard);
}

.ui-card--interactive:hover {
  border-color: var(--ui-border-default);
  box-shadow: var(--ui-shadow-sm);
  transform: translateY(-1px);
}
```

保留 Dashboard 现有卡片精华：

- 图标色块与大数字。
- 右下角低透明度水印图标。
- 中英双层标题。
- hover 时轻量图标缩放。
- 不再默认叠加粗像素框、强发光和大旋转。

### 11.2 按钮

- 主按钮可以保留像素按压反馈，但外形使用现代小圆角。
- 次按钮使用细边框和轻背景。
- 危险按钮必须使用明确红色语义。
- 图标按钮点击区域不小于 32×32px。
- 操作成功或失败必须接入统一 Toast。

### 11.3 输入与选择器

- 默认 1px 细边框、小圆角、中性背景。
- Focus 使用 2px 半透明强调环，不能只依靠颜色变化。
- Label 使用 Sans 正文或 Pixel Label，整个表单必须统一。
- 下拉层使用 elevated 背景、`md` 阴影和 10px 圆角。
- 校验错误在控件下方显示，不用 Toast 替代字段错误。

### 11.4 导航

- 默认使用现代圆角导航项。
- 选中态：淡粉/淡紫背景 + 左侧 3px 品牌色条。
- 当前关键 Agent、模式或节点可追加像素边框强调。
- 设置和高级功能采用可折叠二级导航。
- 收起后只显示图标，Tooltip 必须提供完整名称。

### 11.5 Toast

- 成功：轻量绿色图标，不遮挡主操作。
- 失败：明确错误摘要，可提供“详情”操作。
- 警告：仅用于用户必须注意但不阻断的情况。
- 同一操作不得在组件层和 composable 层重复弹 Toast。
- 默认位置建议右上角，避开标题栏窗口控制区。

### 11.6 空状态

保留 `PEmpty` 的猫爪、sparkle 和像素跳帧动效，但降低同时播放的动画数量：

- 主插画最多一个呼吸动画。
- 文案必须说明为什么为空，以及下一步可以做什么。
- 有明确操作时提供主按钮。
- 技术页面可使用更克制的无动画空状态。

## 12. 二级页面与对话框规范

### 12.1 Slide-over 优先

适用于：

- 对话调试详情。
- 记忆详情与编辑。
- 模型配置编辑。
- Agent/节点详情。
- 日志筛选详情。
- 据点成员与设施详情。

### 12.2 Modal 保留场景

- 删除、重置、覆盖等危险确认。
- 必须立即决策才能继续的阻断操作。
- 小型、短流程的输入。

### 12.3 悬浮层视觉

- 遮罩：浅色 `rgba(15,23,42,.34)`，深色 `rgba(0,0,0,.56)`。
- 模糊：6px–10px。
- Slide-over 不使用像素边框。
- 关闭按钮可以使用像素图标，但容器保持现代风格。
- 面板内部的关键选中项可使用像素边框。

## 13. 功能页面设计指导

### 13.1 对话

对话是**角色工作区**，结构采用“角色舰桥 + 伙伴关系栏 + 聊天画布 + Mini Command Deck”，不再使用两个并列的普通列表区。

- **优先级**：消息正文 > 输入动作 > 当前角色状态 > 当前会话历史 > 角色列表。
- **角色舰桥**：顶部显示当前角色、会话标题、当前任务/工具状态与搜索。
- **左侧伙伴关系栏**：当前角色展开显示其历史，其他角色以紧凑行展示历史摘要。
- **聊天画布**：允许使用特定角色环境光和极弱网格纹理，正文区域保持中性安静。
- **消息气泡**：用户气泡现代、轻快；Agent 气泡保留 3px 角色生气色首选轨，像素边框只用于头像和最少量强调点。
- **工具轨迹**：调用默认显示为“工具轨迹”式状态路径，不只收成长折叠块；可折叠保留详情，但不以复杂调试弹窗作为主体验。
- **输入区**：升级为 Mini Command Deck，支持附件、语音、工具运行状态反馈，不再是一个中性文本框。
- 不显示总览粒子；运行状态、发送状态和加载动画可使用克制 steps 动效。

### 13.2 总览

总览是唯一允许完整品牌氛围的工作页：

- 保留环境光、像素粒子、大数字和低透明度装饰图标。
- 天气、新闻、近期对话、系统健康使用统一栅格。
- 动画应位于背景层，不覆盖文字。
- 统计卡片保留现有 Purple/Sky/Orange 等语义，但降低背景饱和度。

### 13.3 日志

- 时间分组“今天 / 七天内 / 更早”继续保留。
- 会话卡改为现代列表卡，头像和选中态保留像素特色。
- 展开对话使用清晰时间线，不堆叠强阴影。
- 调试详情改为 Slide-over。
- 删除继续使用乐观更新、失败回滚和统一 Toast。

### 13.4 记忆

- 保留类型色、重要度、情感标记和标签系统。
- 列表与图谱属于同一页面的视图切换。
- 详情改为 Slide-over，避免脱离记忆上下文。
- 图谱发光只用于节点，不扩散到整个页面。

### 13.5 设置

- 采用设置分组 + 现代表单，不使用大量像素框。
- 一个页面只突出一个主保存操作。
- 高风险配置需明确说明影响范围。
- 连接测试、保存、删除必须有状态反馈。

### 13.6 据点

据点不是另一个聊天页，而是多 Agent 的设施工作区，采用“设施导航 | 探讨工作台 | 成员雷达”。

- 左侧设施强调功能语义（大厅、工坊、数据中枢），不是普通频道列表。
- 中间工作台区分用户指令、Agent 回复和共同行动摘要；共同成果用 Stream Card，不使用普通聊天气泡代放。
- 右侧成员雷达显示角色当前职能、所在设施、在线状态和运行任务。
- 工具事件与同调状态以角色轨迹突出，不混在普通消息堆中。

### 13.7 终端

- 保留独立暗色主题、等宽字体、TAG 着色、链接和 CRT 扫描线。
- CRT 纹理透明度必须极低，不能影响选中文本。
- 支持左键选择、右键复制、链接系统浏览器打开。
- 终端作为专业工具区域，不叠加萌系粒子。

## 14. 图标、插画与二次元元素

### 14.1 图标

- 继续使用 `PixelIcon` 作为主图标系统。
- 同一工具栏内图标大小统一。
- 常规图标不持续动画；运行、同步、加载等状态可动画。
- 不能仅用图标表达危险操作，必须有 Tooltip 或文本。

### 14.2 Agent 头像

Agent 头像是二次元感的核心视觉锚点：

- 导航、聊天、状态卡和据点中保持一致形象。
- 普通头像使用现代细边框；选中头像使用像素边框与轻 Glow。
- 头像周围不同时叠加旋转、脉冲、粒子和多色渐变。

### 14.3 装饰元素

- 猫爪、sparkle、thought、heart 作为彩蛋，不承担主信息。
- hover 彩蛋每个组件最多一个。
- 装饰透明度通常不超过 10%。
- 动画装饰不得进入日志正文、代码、终端和表单输入区域。

---

## 15. 可访问性与交互底线

- 正文文本与背景保持足够对比度。
- 所有交互元素必须有键盘焦点态。
- 图标按钮必须设置可访问名称。
- 点击区域最小 32×32px，主要移动端操作建议 44×44px。
- 颜色不能作为唯一状态表达，需配合图标或文字。
- Slide-over 和 Modal 必须管理焦点、支持 `Esc`、锁定背景滚动。
- 动画遵守 `prefers-reduced-motion`。
- Toast 不得是操作结果的唯一持久记录；重要错误应在页面内保留状态。
- 支持文本选择的内容区不得使用全局 `user-select: none`。

## 16. UX 行为规范

### 16.1 操作反馈

| 操作类型                   | 反馈方式                               |
| -------------------------- | -------------------------------------- |
| 保存、创建、复制、删除成功 | Toast + 立即更新本地 UI                |
| 异步加载                   | 局部 Skeleton/Spinner，不阻断整个页面  |
| 删除失败                   | Toast + 乐观状态回滚                   |
| 字段校验失败               | 字段旁错误信息                         |
| 危险操作                   | 确认 Modal                             |
| 长任务                     | 可持续查看的任务状态，不只显示短 Toast |

### 16.2 状态同步

- 一个页面中的操作必须立即同步相关组件。
- 删除消息对时，前端必须同时删除 user 与 assistant 项。
- 总览统计必须使用后端真实状态，并响应全局刷新事件。
- 切换 Agent、节点、Thread 后，相关内容不得残留上一上下文的数据。

### 16.3 导航状态

- 当前功能必须可通过 URL 恢复。
- 浏览器刷新后保持当前页面和必要筛选状态。
- Electron 与浏览器使用同一信息架构。
- 对话页可自动收起主导航；用户固定展开后应记住偏好。

## 17. 推荐与禁止示例

### 17.1 推荐

- 中性背景 + 白色卡片 + 低饱和粉色选中态。
- 默认细边框，选中 Agent 使用像素轮廓。
- 右侧 Slide-over 查看日志调试详情。
- 总览页保留环境光，配置页保持纯净。
- 像素按钮下沉反馈与现代圆角共存。
- 二次元头像作为视觉焦点，而不是整页铺满萌系装饰。

### 17.2 禁止

- 每张卡片都使用 `pixel-border-moe`。
- 一张卡片同时拥有粗像素框、彩色 Glow、大渐变、旋转图标和粒子。
- 使用像素字体显示长段设置说明。
- 删除成功后 UI 不立即更新。
- 普通详情全部使用阻断式 Modal。
- 深色主题简单反转颜色而不调整边框、阴影和 Glow。
- 为追求现代感彻底删除现有像素图标、按压动画和品牌色。

## 18. 迁移执行规则

1. 先建立 `--ui-*` 语义令牌和深浅主题，不直接重写所有业务组件。
2. 新建 MainView 框架组件，验证导航、卡片、Slide-over 和主题切换。
3. 优先迁移对话、总览、日志三个高频页面，形成样板。
4. 将现有 `PCard/PButton/PDialog` 扩展为现代与像素两种明确模式，而不是复制新组件。
5. 保留原有 Dashboard 组件中的优秀结构，逐项替换外观令牌。
6. 每迁移一个页面，同时检查深色主题、键盘操作、窄屏布局和 Toast 行为。
7. 未完成迁移前，新旧视觉可以短期共存，但同一组件内不得混杂两套无语义的样式。
8. 完成后删除不再使用的硬编码颜色和重复样式。

## 20. 最终设计判断标准

如果一个页面看起来像传统企业后台，说明二次元和像素品牌表达不足；如果它看起来像充满粉色描边的像素游戏菜单，说明现代工作站感不足。

正确结果应当是：

> 第一眼是一个现代、可靠、空间层级清晰的 AI 工作站；第二眼能发现像素图标、角色头像、跳帧反馈、粉蓝紫品牌色和细微彩蛋；长期使用时这些特色不会妨碍阅读和操作。
