# TTS 多协议接入与自定义 API 整体规划

> **状态**：首批统一调度、内置 HTTP 适配器与自定义字段已实施；高级流程与播放流化仍为 TODO。
> **记录日期**：2026-10-24。
> **范围**：第 1—12 节保留整体规划；第 13 节记录本轮实际交付，未列入实际交付的规划不能视为已实现。
> **说明**：本轮按官方协议实现并以模拟服务验证，未调用真实付费服务，未构建打包。

## 1. 目标

- 普通用户选择现成适配器和声音预设即可使用。
- 高级用户可配置自定义 API、请求字段、返回字段和模型能力，接入中转站或自建服务。
- 特殊鉴权、异步任务和流式协议保留代码适配器扩展途径。
- 区分服务连接、接口协议、模型、音色与声音预设，避免更换音色就重配整套 API。
- 复用现有 AIOS Capability、资源交付和播放边界；Electron 和 Docker 共用服务端配置与执行逻辑。

## 2. 已确认的当前基础与缺口

| 位置 | 当前情况 | 规划处理 |
| --- | --- | --- |
| `services/voice/ttsService.ts` | 固定 Provider 联合与 switch；Edge、OpenAI 有实现，Azure/local 分支报未实现；未知 Provider 回退 Edge | 引入适配器解析；保留可用旧实现，取消未知配置的隐式换服务 |

| `audioDeliveryService.ts` | 已将合成音频注册成 Asset，经目标 Node 的 `audio.output` 播放；扩展名只区分 ogg 与 mp3 | 复用交付；补齐编码、容器、采样率和实际文件扩展名 |
| 多个调用入口 | 自动口语回复、聊天播放、选区朗读、实时会话均调用 TTS | 汇总到同一编排服务，验证取消、绑定和输出格式一致 |

配置保存、后端热更新、Capability 健康状态及前端刷新需要作为一条完整链核查；不能以设置页保存成功代替运行时生效。

## 3. 配置对象与上下级

| 对象 | 负责什么 | 不应承担什么 |
| --- | --- | --- |
| `TtsConnection` | 地址、凭据引用、连接级 Headers、超时、启停 | 不把厂家名称等同于协议，不固定唯一模型 |
| `TtsApiProfile` | 适配器 ID、请求模板、响应映射、发现模型/音色的方法 | 不保存角色人格，不直接执行自定义 JavaScript |
| `TtsModel` | 连接与 API Profile 引用、模型 ID、能力描述、限制、发现来源 | 不根据模型名称猜能力 |
| `TtsVoicePreset` | 模型引用、音色 ID、参考资源、参考文本、默认情感/指导及参数 | 不重复保存 API Key；模型绑定明确，跨模型复用需重新校验 |
| `TtsBinding` | 全局默认与 Agent 的声音预设选择 | 不从全局当前角色推断请求归属 |

层级：连接包含模型；模型选择 API Profile 并定义能力；声音预设绑定模型；角色绑定声音预设。允许同一连接下的模型使用不同 Profile。

第一版提供全局默认与 Agent 绑定；会话临时覆盖作为后续能力，调用合同预留显式 presetId。每次合成固定配置修订快照，编辑预设不改变正在执行的请求。

## 4. 模型能力与动态参数

能力描述包含支持状态、字段定义、限制和来源。支持状态为 `supported / unsupported / unknown`；未知与不支持分别处理，不把未知直接隐藏成不可用。

主要能力域：

- 文本：语言、SSML、文本格式、长度及计量单位，分段约束。
- 音色：固定 ID、可查询音色、服务端训练声音、参考音频克隆。
- 参考输入：单个/多个音频、参考转录文本、语言、用途、时长和 MIME 限制。
- 演绎：情感枚举、强度、自由情感描述、风格自然语言指导；区分声音身份描述与当前语句的表演指导。
- 韵律：语速、音高、音量及各自单位/范围，不把所有接口强行换算成同一数字。
- 输出：容器、编码、采样率、声道、PCM 位深/字节序，以及完整结果、异步任务、流式支持。

字段 Schema 提供稳定 ID、语义用途、类型、默认值、选项、范围、单位、必填条件、显示条件及资源类型。保留命名空间扩展字段，不为每家私有参数无限增加核心顶层字段。

常见条件：参考音频非空时要求参考转录；选定音色后禁用音色克隆参数；特定模型才允许演绎指导。条件使用有界、可校验的声明式规则。

能力来源保留出处和修订：内置适配器默认 → 模型描述/可信元数据 → 用户覆盖。接口列表只返回模型 ID 时，不据此虚构能力。用户覆盖可以声明待验证参数，不能赋予适配器尚未实现的传输方式。

## 5. 高级用户自定义 API

### 5.1 请求配置

- URL/路径、HTTP 方法、Query、Headers、凭据绑定。
- JSON、表单和 multipart 请求体；变量按结构化值绑定，保持对象、数组、数字、布尔和空值类型。
- 文本、模型、音色、情感、指导、参考音频、参考文本以及扩展参数可映射到任意允许的字段路径。
- 支持静态字段、缺省值和条件省略，定义覆盖顺序；敏感 Header 由连接提供。
- 用户文本按值传入并正确转义，不拼接成 JSON 源码，不开放 eval 或任意 Node 脚本。

### 5.2 响应配置

按明确模式选择：原始音频二进制、JSON 中的音频 URL、JSON 中的 Base64。定义音频字段路径、格式/采样率字段路径、业务成功条件、错误码与错误消息路径。

字段选择器先提供确定的对象/数组路径，不把任意表达式执行器带进来。找不到必需字段、Base64 无效、返回 HTML/JSON 错误页等必须明确失败，不能保存成伪音频。

下载音频由服务端执行并转为受控资源；下载地址不自动继承上游 API Key。需要下载鉴权时单独配置，重定向同样遵守凭据边界。显式配置的本地 TTS 地址应可用于自建服务；Docker 的 localhost 含义需在连接测试中说明。

### 5.3 复杂流程

初期自定义 Profile 只覆盖单次 HTTP 请求及结果解析/音频下载。后续扩展有界步骤：可选参考音频上传 → 提交合成 → 提取任务 ID → 限时轮询 → 下载结果 → 可选取消。

特殊签名和专用 WebSocket/流协议交给代码适配器。配置不能宣称已兼容所有异步或实时 TTS API。

## 6. 模型与音色发现

- 三种来源并存：接口发现、适配器预设、手动添加。
- 发现接口的路径、请求和 ID/名称字段可自定义，不固定只能 `/models`。
- 模型和音色列表分别配置；没有查询接口时允许手填 ID 和自定义显示名。
- 刷新列表保留用户维护的能力、预设和手动项，不自动删除已绑定对象。
- 可记录发现时间、失败原因和待确认状态；列表获取成功与实际合成成功分别呈现。
- 不与聊天模型池混成一个无类型列表；可以复用连接管理的基础组件和凭据存储方式。

## 7. 合成、资源与播放的统一链

```text
调用入口（明确 Agent / Thread / 播放目标）
  → 解析声音绑定与配置修订
  → 清洗口语文本、校验能力/参数/资源
  → 构造规范化合成请求
  → 内置适配器 / 自定义 HTTP Profile / 扩展能力节点
  → 校验并归一化音频结果
  → 服务端资源注册 / 音频交付
  → 浏览器或 Electron 播放目标与播放回执
```

规范化请求包含 text、presetId、agentId、threadId、requestId、参数/参考资源引用及取消/截止时间上下文。保留 `audio.tts.generate` 作为统一能力入口，扩展合同遵守既有版本兼容规则。

完整音频先归一为音频结果与资源信息，保留 MIME、容器/编码、采样率、声道等元数据。PCM 必须有足够解码信息；不能统称 mp3，也不假定所有客户端都能直接播放上游格式。

前端播放、后端合成、资源保存各自承担明确职责。浏览器和 Electron 不直接持有第三方合成凭据，不由浏览器直接请求中转站。

参考音频始终由客户端上传字节，服务端生成资源引用；不接收客户端本地路径作为服务端文件。适配器根据接口要求发送 multipart、内联数据、受限可访问地址或上游资源 ID。需要上游抓取时，不能简单把本机 localhost 资源 URL 交给外部服务。

普通回复继续使用已清洗的口语文本和用户声音预设。若后续让 Agent 指定语气，只开放当前能力允许的规范化字段，不要求 Agent 拼厂家 API，不默认让 Agent 分析参考音频内容。

## 8. 生命周期与可靠性

- 创建、校验、发送/等待、音频就绪、交付、播放完成、取消和失败分别可观测；合成完成不等于播放完成。
- 取消向上传、请求、轮询和播放传播；不支持远端取消时，停止本地等待并丢弃迟到结果，明确可能仍被上游计费。
- 请求绑定 Thread、Agent、修订和播放目标；明确桌宠独占播放策略，避免旧请求在新回复后突然播放。
- 默认不对未知结果的付费合成自动重试；只有明确可安全重试或服务支持幂等时重试。格式错误不反复重发生成。
- 未知配置、模型失效和参数不支持明确报错；跨服务回退须由用户显式配置。
- 状态更新区分配置完整、连接可达、模型列表可取、合成验证成功。避免把“填了 Key”显示为“已验证可用”。
- 日志记录阶段、耗时、配置修订和脱敏错误；限制正文、参考音频和凭据的日志输出。
- 若引入缓存，键需包含文本、清洗版本、模型/预设修订、全部生效参数与参考资源摘要；缓存作为后续优化，不阻塞首版闭环。

语音功能保留在现有语音设置入口，TTS 与 ASR 的配置职责分开；本轮不扩展 ASR 协议系统。

| 区域 | 内容 |
| --- | --- |
| 语音输出 | 总开关、全局默认声音、角色绑定、试听与播放状态 |
| 服务连接 | 已配服务、连接状态、凭据、内置/自定义协议选择 |
| 模型与能力 | 获取列表、手动添加、能力说明、限制和覆盖配置 |
| 声音预设 | 模型、音色、参考音频/转录、演绎指导、动态参数及试听 |
| 自定义 API 编辑器 | 请求配置、输入映射、响应映射、发现配置、脱敏请求预览与联调结果 |

自定义编辑器位于当前连接的高级配置中，不要求普通用户理解字段映射。先显示常用字段，复杂结构提供源码编辑与明确校验；两种视图共用同一配置模型。

试听展示实际生效的模型/预设、状态、错误阶段和音频结果，允许取消与重试。连接检查、获取模型和真实合成分别是不同操作，真实合成由用户点击触发。

沿用 infOS 直角、像素标签、轻硬阴影、现有图标/字体与深浅主题；复用真正的 PCard/PButton 等组件，适配自定义背景材质。只为条件差异生成字段，不把整个页面变成通用 JSON 表单。

## 10. 保存、迁移与扩展

- 使用带 schemaVersion、稳定 ID 和修订号的对象；Repository 负责持久化，Service 负责迁移和配置解析，Router 只校验/分派。
- 将现有 `tts.*` 迁为兼容连接、模型和声音预设；保留原配置以便回退，迁移幂等。
- Edge 与现有 OpenAI 实现先迁入适配器，行为保持可追溯；旧 `tts-1` 作为旧配置迁移值，不作为所有新连接的固定值。
- Azure/local 等尚未实现的配置标记不可用或待配置，不伪装成已可用。
- 配置保存采用按对象修订提交，运行时热更新并刷新 Capability 健康状态；核查当前共享防抖计时器对多个设置连续保存的影响。
- Profile 与预设允许复制、导入导出和社区分享；导出默认不带密钥与本地个人参考音频，缺失凭据/资源映射需显式补齐。
- 代码适配器复用已有 Package 信任、启停和 `capability-provider` / CapabilityDirectory / BoundPort 边界；需要额外注册端口时单独定义窄合同，不把 AppContext 暴露给适配器。
- 不依赖安装版源码可写，不把 JSON Profile 转成运行时任意脚本；Electron/Docker 使用可写数据目录保存用户配置和资源。

## 13. 首批实现与使用说明（2026-10-24）

### 13.1 实际交付

- `TtsService` 是统一调度入口，Edge TTS 与 HTTP 服务均通过 `TtsAdapterRegistry` 执行；不再以 switch 分别维护业务链路，也不再因未知服务配置暗中切回 Edge。
- 每次调用先固定工作区快照，再解析显式预设、角色绑定或全局默认；统一处理双并发、最多 16 个等待请求、超时与取消。
- 连接、协议、模型、声音预设、角色绑定分别保存于 `tts.workspace.v1`；旧 Edge/OpenAI 配置兼容加载，第一次保存新工作区后优先使用新配置。旧 OpenAI 保留 `tts-1`。
- 首批内置：Edge、OpenAI Speech、MiMo V2.5 的预置/VoiceDesign/VoiceClone、百炼 Qwen HTTP、MiniMax Speech HTTP、StepAudio Speech HTTP。
- 自定义单次 HTTP 支持 JSON、URL 编码表单、multipart、SSML/XML 请求体，支持路径、Query、Headers、结构化请求体变量以及二进制、Base64、Hex、URL、SSE 返回。
- 参考音频由客户端上传 WAV/MP3，经服务端 Asset 注册、持久保存后引用；MiMo 克隆从该资源生成 Data URL，不读取客户端路径。
- 合成结果统一校验容器与 MIME；当前裸 PCM 合同明确为 PCM16LE 单声道，并封装 WAV 后交给既有 Audio Asset/播放链路。
- 试听、消息播放、选区朗读、自动口语回复、实时语音会话及 `audio.tts.generate` 接到同一服务。Capability 的角色取自信封主体，信号与 Deadline 进入调度层；配置保存会刷新 Offer 健康状态。

### 13.2 设置入口与生效

在“语音功能 → 语音合成”添加服务预设，填写 API Base、API Key、模型与音色。MiMo VoiceDesign 填写音色描述；VoiceClone 上传参考音频。MiniMax、阶跃可填写各自已创建的音色 ID，本轮不自动创建这两家的云端音色。

“设为默认”决定未绑定角色的声音。“当前角色的声音”可另选预设；选择“跟随全局默认”删除该角色的单独绑定。修改后点击“保存配置”，或点击“保存并试听”；试听不会因修改表单自动调用上游。

连接可被多个模型/声音预设复用；高级字段中的连接 Headers 随连接共享。请求扩展字段用于各家额外选项，不能覆盖内置适配器负责的模型、文本、音色和返回方式；需要重写结构时选择自定义 HTTP。

### 13.3 自定义协议示例

在自定义预设的“高级字段 → 自定义协议配置”中填写以下对象。示例请求使用自定义 `content` 字段，并从响应第一项的 `sound` 解码 Base64 音频：

```json
{
  "path": "/tts/{{voice}}",
  "method": "POST",
  "headers": { "X-Api-Key": "{{apiKey}}" },
  "query": { "model": "{{model}}" },
  "bodyType": "json",
  "body": {
    "content": "{{text}}",
    "speed": "{{speed}}",
    "style": "{{instructions}}",
    "options": "{{extra}}"
  },
  "response": {
    "mode": "json",
    "encoding": "base64",
    "audioPath": "result[0].sound",
    "format": "wav",
    "successPath": "code",
    "successValue": 0,
    "errorPath": "error"
  }
}
```

- 完整 `{{变量}}` 按值替换，因此 `{{speed}}` 保留数字，`{{extra}}` 保留对象；字符串内部插值生成字符串。用户文本不会再次作为模板求值。
- 变量：`text`、`model`、`voice`、`apiKey`、`speed`、`rate`、`pitch`、`format`、`language`、`instructions`、`emotion`、`referenceAudio`、`referenceText`、`extra`。
- `referenceAudio` 是上传资源的音频 Data URL；multipart 请求中作为完整字段值使用时转换成文件，JSON 中则保持字符串。
- 路径变量进行 URL 编码；Query 由 URLSearchParams 编码；XML 变量进行 XML 转义。不会执行 JavaScript 或字段表达式。
- 选择器使用 `result.audio`、`result[0].audio` 这种确定路径。业务状态通过严格值比较判断，不依据错误文案分支。
- 二进制返回：`response: { "mode": "binary", "format": "mp3" }`。
- URL 返回：`mode: "json"`、`encoding: "url"`，`audioPath` 指向下载地址；下载不继承 API 凭据。
- SSE 返回：`mode: "sse"`，`encoding` 选择 `base64` 或 `hex`，`audioPath` 指向每个事件内的音频字段。默认 `chunkMode: "append"`；只有最后一条有效音频是完整聚合结果的协议才使用 `replace`。
- PCM 返回：`format: "pcm"`，显式填写 `sampleRate` 或 `sampleRatePath`。仅接受 PCM16LE 单声道；其他 PCM 合同需另行扩展，不能以错误采样参数伪装播放。
