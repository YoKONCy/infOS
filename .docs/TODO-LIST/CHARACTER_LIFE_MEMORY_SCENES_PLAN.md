## 1. 目标与架构边界

据点提供生活模式与协作模式。角色可以日常相处、参与共同活动，也可以接受明确目标、分工执行并交付成果。活动的发展形成有来源的角色亲历，由后台整理事件记忆与日记，主动记录的简短要点写入工作区记事本。

角色在据点中的持续性直接关联其唯一 MainThread。私聊与据点共同推进该角色的当前心流，群聊参与状态关联同一主线。活动、分工和等待通过各自的权威对象与引用接续。

PrincipalAgent 通过 `agentId` 关联 Identity、Memory、Workspace、Capability 等资源。角色长期资源各自持有权威数据，群聊持续状态以 `mainThreadId` 标识归属，主线 `generation` 约束重置后的有效提交。

### 已确定的设计边界

- 每个角色通过唯一 MainThread 参与据点，生活与协作共同推进该角色的群聊持续状态。
- 私聊与据点共用 MainThread 下的当前心流，表达角色此刻的关注、理解和行动意图。
- 心流可简短引用文件路径、工具、命令及已有操作或任务标识，说明它们与当前判断和下一步意图的关系。
- 主动要点通过记事本维护，任务、活动、执行和等待事实由对应领域持有。
- 房间保存公共消息、环境、事件和在场关系，角色亲历引用当时实际可见的公共事实。
- 协作任务保存目标、分工、依赖、成果、验收和运行事实，角色参与任务时使用自身主线身份。
- 主会话与据点直接编译同一角色的近期聊天原文，角色亲历与主线私聊各有权威来源。社交使用所属应用的聊天资料，长期认识通过角色记忆及明确交接接入。
- Stronghold 属于主应用内部场景，使用现有 `group` Channel，复用 ContextCompiler、KernelScheduler、Execution、Task 和 Outbox。
- 房间模式、Thread 交互模式、执行权限和任务内职责分别建模。负责人、执行者与复核者表达当前协作职责。
- 事件记忆在 Agent 工具侧提供只读查询与召回，事件新增和修订由后台来源加工处理。
- 共享事实的 Agent 修改入口限于真实主 Thread 执行，并结合当前场景与资源授权校验。
- 日记沿用现有后台维护，记事本位于角色工作区的一个直接下级目录，包含一个主 Markdown 文件和同级附页。
- 工作上下文提供独立清理工具，持久记录后续请求的工作轨迹选择边界。
- SideThread 保有局部历史与任务现场，可按权限读取角色记忆及使用工作区记事本。

自动聊天补记的来源已按主 Thread 筛选，日记与关系维护由角色级调度执行。后续记忆职责采用本规划第 7 节的工具与来源合同。

| 对象 | 权威内容 | 归属与关联 |

| 角色当前心流 | 此刻的关注、理解、行动意图与必要引用 | 唯一 `mainThreadId`，私聊与据点共用，携带代次和修订 |
| 群聊参与关联 | 在场、注意力及活动、分工和等待引用 | 关联角色 MainThread，按房间和事项说明参与对象 |
| 共同活动 | 事情身份、参与者、公共进展及相关资料 | `activityId`，引用发起场景 |
| 协作任务 | 目标、负责人、任务修订、完成条件与运行状态 | `collaborationId`，关联房间和活动 |
| 成员分工 | 接受状态、依赖、工作资料、提交与复核记录 | `assignmentId`，关联成员 MainThread |
| 定向消息 | 发送者、接收者、请求类型、来源、回执与消费位置 | 稳定消息 ID，接收者绑定 MainThread |
| 成果 | 提交者、来源 Execution、内容引用、版本与验收意见 | 稳定成果 ID 与资源引用 |
| 亲历 | 角色在事件发生时获得的事实引用和可见关系 | 角色 MainThread 与来源事件 |
| 事件记忆 | 个人亲历、阶段叙述与后续理解 | 角色事件库，后台按有效来源维护 |
| 共享事实 | 跨角色共用的对象与已确认信息 | 共享 Facts Store，主线执行按权限修改 |
| 日记 | 当天经历的人格化回顾 | 角色工作区 `dailynotes/` |

| 经历关联 | 同一件事跨阶段的来源与认识变化 | 通过现有事件来源、关联边和修订链定位经历及认识变化 |

| Execution | 本次输入快照、工具过程、提交与投递结果 | 一次逻辑执行 |

### 3.1 MainThread 持有的心流与参与关联

每个角色的 MainThread 持有一份当前心流，私聊与据点共同读取和更新。正文随注意力与思路变化更新，跨回合、执行与重启接续，提交核对主线代次和状态修订。

群聊参与关联通过 `roomId`、`activityId`、`collaborationId` 和 `assignmentId` 定位当前参与对象。活动、任务和等待的实际状态从各自权威入口读取，心流表达角色当下怎样理解和处理这些事项。

旧协作稿中的“独立成员 Thread”方案调整为 MainThread 归属、分工工作资料与 Execution 的组合。协作任务负责保存工作事实，角色心流负责表达其当前理解、行动安排和等待原因。

具体正文格式和更新参数在合同阶段定稿。来源场景、主线代次及修订由受信执行上下文提供，原始聊天分别按场景装配。当前心流的来源与可表达范围参与上下文选择和公开投递约束。

#### 心流中的文件与操作引用

- 引用紧贴当前判断或行动意图，正文保持简短。
- 文件引用使用可定位的路径，相对路径附所属工作区信息。需要正文时，通过获准文件工具读取。
- 操作可引用工具名、命令，以及已有的调用、任务或成果标识。具体标识从当前执行已提供的资料取得。
- 实际执行状态、操作结果和完成情况通过工具回执、任务或成果记录核对。
- 主动记下的要点通过记事本维护，经历的长期沉淀按事件记忆与日记职责处理。

提示词建议采用以下约定。

> 心流描述你此刻的关注、理解和行动意图。涉及文件或操作时，可以引用路径、工具名、命令及已有标识，简短说明它们与当前思路的关系。需要正文或执行操作时，使用当前获准的工具，并依据真实回执判断结果。主动记录的要点写入记事本。

例如，“我还拿不准问题出在启动参数还是配置读取，先查看对应工作区的配置文件”，可以附上实际配置路径和准备使用的读取工具。“我想把旅行建议解释得更贴近主人的偏好”，可以引用 `notes/旅行.md`，再按需读取相关内容。

### 3.2 场景资料与模型输入

每次据点执行确定角色 MainThread、代次、房间、模式版本、触发来源、可见消息范围、关联活动或分工及结果目的地。

ContextCompiler 从以下来源装配本次输入。

1. 角色身份与获准的长期状态。
2. 当前房间中该角色可见的消息、事件、环境和成员信息。
3. MainThread 当前心流，以及与本次参与有关的活动、分工和等待引用。
4. 当前协作的目标、本人分工、必要依赖和成果引用。
5. 按来源、授权、相关性与预算选取的事件记忆及共享事实。
6. 本次实际开放的工具、审批规则和资源范围。
7. 按已定注入规则读取的记事本主文件，以及明确读取的附页内容。

目标、分工、状态、消息和成果通过统一编译入口参与预算与 Manifest。同一角色的主线私聊与据点亲历直接读取相关近期原文，编译时标明场景、时间、发言者及回应对象，按来源去重。主线消息与房间消息各自保存权威正文，互通通过来源引用和惰性编译完成。SideThread 与社交、其他子应用继续使用各自的历史范围；社交历史取自平台会话入口。

跨场景条数按当前场景实际选入的正式聊天消息数取二分之一，向上取整，复用按消息条数读取的接口。空窗口采用现有 Channel 默认消息窗口数作为基准。整条消息进入统一 Region 和最终模型请求选择。

工作执行轨迹按模式、来源有效性及持久清理边界选择。日常交流可以从记事本与相关事件中取得简洁线索。

## 4. 生活与协作模式

### 4.1 首版建议

房间默认使用生活模式，由明确的多人委托进入协作，协作完成结算后回到生活模式。每个房间同时推进一项当前协作，暂停或已结束的任务保留记录和恢复入口。

| 方面 | 生活模式 | 协作模式 |
| --- | --- | --- |
| 参与目的 | 日常相处、共同活动与交流 | 完成明确目标 |
| 参与依据 | 提及、关系、亲历、心流与注意力 | 分工、请求、依赖、进展与等待条件 |
| 发言内容 | 分享、询问、接续话题与活动 | 问题、安排、阻塞、阶段结果与成果 |
| 组织程度 | 活动按实际需要逐步形成 | 明确负责人、参与者、分工和完成条件 |
| 推进方式 | 正常交流与获准的主动参与 | 任务状态机与有效请求驱动 |
| 结束方式 | 自然结束、离场、暂停或主动结束活动 | 完成验收、取消或显式暂停 |

模式变更影响房间的参与与调度策略。工具权限由角色、Channel、资源授权和执行审批共同确定。

### 4.2 进入协作

用户可以通过明确操作或自然语言委托发起。服务端核对操作者、原始委托、参与者与任务来源，并保存稳定的启动身份。

进入前需要取得共同目标、参与角色，以及可判断的完成条件。分工可以在准备阶段由负责人提出，成员分别接受。

“Pero 查路线，Nana 查住宿，最后给我一份行程”可以直接建立协作。必要信息缺失时，通过正常对话补齐。日常旅行讨论、游戏和共同娱乐继续按生活活动推进，单角色普通请求使用现有任务系统。

角色可以提出协作建议，用户接受后启动。自然语言识别产生待校验的结构化意图，模式与任务变更经领域入口提交，并引用对应用户消息及修订。

### 4.3 回到生活

| 触发情况 | 状态处理 | 房间模式 |
| --- | --- | --- |
| 成果通过验收，协作完成 | 保存验收、成果与最终进展 | 生活 |
| 用户取消协作 | 保存取消原因，结算关联分工和在途工作 | 生活 |
| 用户要求暂停或切回日常 | 保存进展、等待原因及恢复条件，暂停协作 | 生活 |
| 等待用户、外部任务或成员结果 | 保存等待现场，释放本次执行占用 | 协作 |
| 执行失败或出现阻塞 | 保存真实失败、重试与调整事项 | 协作 |
| 成员提交成果，等待验收 | 保存提交及复核资料 | 协作 |

等待和阻塞期间，角色可以回应普通交流。当前协作的状态继续由任务账本持有。

切回生活时，先记录暂停或取消意图，再按现有执行交接规则收口在途调用，保存实际产生的结果与回执，随后提交模式变化。房间模式修订用于参与策略校验，主线代次用于角色主线生命周期校验。

### 4.4 恢复协作

用户明确选择恢复，或通过消息指向原协作时，核对任务修订、参与者、分工、来源与成果，再恢复推进。指向多个任务时通过对话确定目标。

仍处于等待中的协作，可由约定的结果或事件触发后续执行。用户主动暂停并切回生活后，迟到结果保存为到达记录和提醒，由用户明确恢复后接续。

房间模式、当前协作引用和有关业务状态在同一领域事务中转换，Outbox 通知调度与投影。启动、暂停、恢复和结束均使用幂等身份。

## 5. 生活互动、活动与注意力

据点围绕角色长期同住、彼此熟悉和共同经历组织生活。角色可以自然接话、旁听、做自己的事、等待伙伴和延续已有话题。详细状态、事件、事务、生命周期与实施合同由[据点生活设计](./STRONGHOLD_LIFE_DESIGN.md)维护，本节汇总与总规划的衔接。

生活闭环为同处、发起、回应与加入、关注或等待、事件接续、自然收束，并形成可追溯亲历。普通闲聊通过交流片段组织，需要公共进展的事情按需建立共同活动。同一房间可以同时存在多项活动。

角色通过唯一 MainThread 持有当前心流和生活参与关联。房间保存公共事实，交流片段保存回应关系和收束状态，活动保存成员及进展，持续关注保存事件条件与消费回执。

进入、离开、环境变化、邀请回应、活动进展及约定到期形成稳定来源的事件。在场关系按事件发生时保存，个人亲历引用公共事实。社交运行时为消息合并、托管等待与恢复提供参考，生活参与方式按据点关系设计。

`inform` 保存信息供后续相关执行读取，`request` 保存需要处理的事项。自然接话候选、请求与关注均携带来源和接收者主线代次，经统一入口消费。

### 5.1 主动行为配置

全局保存主动模式 `off / companion / autonomous` 与据点自由活动默认值，据点自由活动默认关闭。每个角色的两项配置分别支持跟随全局或明确覆盖。主动模式覆盖值为关闭、智能陪伴、自主行动；据点自由活动覆盖值为开启、关闭。新角色默认跟随全局，继承实时解析，恢复继承时移除对应覆盖值。

用户交流、明确委托与自主发起分别识别来源。关闭自由活动只停止该角色的自主发起和自主接续，正常点名与已接受事项沿各自合同处理。

### 5.2 事件驱动的主动与群聊状态机

在场、参与姿态和执行分别建模。在场以角色实际位置为准，参与姿态包含同处、旁听、交谈、专注和休息，执行使用既有 Kernel 生命周期。持续关注独立保存，角色可以边等待伙伴边参与当前交流。

角色在实际执行中同时决定表达对象、回应来源、接续关系及后续安排。服务端核对来源、在场、配置和主线代次，再保存参与决定及发布结果。公开发言、静默处理和后续关注分别保留真实来源。

用户交流、角色明确请求、当前伙伴的新分享和关注命中分别形成接续依据。程序先选择实际接收者，连续输入和同一关注的变化合并处理。回答提交后结算原请求，附和、道谢和结束语推进交流安静状态。

空闲唤醒保留生活发起机会。静默执行后延长空闲等待，有效新事件可提前恢复。角色跨私聊和据点共用认知调度，明确用户输入优先于自主处理，同优先级按受理顺序安排。等待释放执行占用，条件到达再接续。

片段安静、有效期到达和来源已完成由程序推进结算。每次认知执行具有尚未消费的输入、匹配事件或有效空闲机会，调用节奏通过事件准入、输入合并、等待与收束组织。

### 5.3 交流、活动与持续关注

交流片段保存参与者、最近发言关系、待回答事项及活跃、安静、收束状态。角色可以结束本人参与，其他成员的有效交流继续存在。已收束内容后来重新提起时，新片段引用原来源。

共同活动记录内容、发起者、成员及公共进展，支持进行、暂停和结束。成员分别保存参与、旁观、暂离和退出，邀请分别保存接受、拒绝、稍后及有效期。发起者退出后，其他参与者可以继续。

持续关注保存来源、意图、接收者 MainThread 与代次、结构化条件、有效期和消费位置。首版覆盖消息、成员出入、邀请回应、活动变化、环境字段变化和约定到期。程序匹配条件，实际执行理解新内容。

场景动作形成简短公共事件，涉及位置、环境和活动成员的变更使用相应领域操作及回执。事件、状态、亲历和 Outbox 在对应事务中提交，跨领域步骤沿稳定操作身份恢复。

### 5.4 生活持续性与生命周期

用户打断时按实际结果保存已完成步骤，再让出执行占用。活动与有效关注保留当前事实。重启按原请求、发布身份和事件位置恢复，再核对当前配置、位置及对象状态。

主线清空使旧代次参与和关注结束有效调度，公共活动及历史事实保持来源，旧成员参与标记中断，当前代次通过真实加入或明确恢复建立新关联。导入、快照和隐私删除覆盖新增对象及引用。

正式表达和动作事件作为后台亲历来源，日记、事件记忆和记事本继续按第 7 节分工维护。活动权威进展、心流当前理解和公开表达分别读取对应来源。

## 6. 协作运行与成果闭环

### 6.1 目标与分工

协作任务保存目标、任务修订、负责人、参与者、完成条件、关联活动与可用资源。分工保存接收者 MainThread、职责、依赖、接受状态、进展、工作资料和提交引用。

首个闭环采用一名负责人和一名成员。负责人提出分工，成员接受并执行，提交成果后进入验收。后续扩展多人、复核与依赖推进。

负责人、执行者和复核者分别获得必要资料及可执行操作。角色的公开档案、人设和个人认识来自各自的角色资源。

### 6.2 状态与版本

任务状态覆盖准备、执行、等待、阻塞、暂停、待验收、完成、失败和取消。成员分工覆盖待接受、已接受、执行、等待、提交及结算，最终名称与迁移表在合同阶段定稿。

目标或分工调整形成修订，执行输入固定所依据的修订。成员的完成报告、成果提交和验收通过分别记录，公共进度从已确认业务事实投影。

可靠工作复用已有 Task、Execution、Queue 和计划体系，分工与底层执行保存显式关联。计划负责步骤和进展表达，任务与成果账本负责执行和验收事实。

### 6.3 定向通信

消息保存稳定 ID、发送者、接收者 MainThread、所属任务、关联分工、来源和请求关系。接收者的持久收件箱按信息与处理请求区分消费。

接收、处理中、已处理和失败分别保存。对应处理结果成功提交后推进消费位置，恢复沿用原请求和发布身份。进行中的输入快照固定，后到消息在安全边界选取。

每次交办保存原请求者、分工和具体接收场景，回报沿本次请求关联返回。主动回报与显式等待共用原结果的消费身份，恢复时核对既有回执。

来自用户、角色和外部应用的消息保留各自来源及授权主体。其他成员的请求使用接收角色现有权限，经统一能力与审批入口执行。

循环请求与递归委派通过明确接收者、请求结算及等待条件组织，实际执行复用 Kernel 合同。依赖失败、角色不可用或取消时，根据已确认策略进行等待、调整分工或结束。

### 6.4 成果与工作区

成果记录提交者、来源 Execution、资源引用、内容版本、验收意见和结果。文件、文档和其他产物通过明确资源范围与版本引用共享。

个人工作资料由对应工作区持有，共享成果使用发布引用。并发写入核对预期版本、现有内容及冲突，恢复时核对已保存的提交和验收回执。

负责人可见目标、分工、相关进度、阻塞和成果，成员取得本人工作所需资料。公共投影来自任务事实，个人内部过程按授权和诊断入口读取。

## 7. 记忆职责、记事本与工作上下文

### 7.1 四类资料

| 类型 | 内容与载体 | Agent 使用方式 | 维护归属 |
| --- | --- | --- | --- |
| 事件记忆 | 角色亲历、阶段叙述与后续理解，沿用 TDB 及 SQLite 来源账本 | 查询、按来源回读和自动召回 | 后台按主线及其有效亲历来源新增、修订和维护 |
| 共享事实 | 人物、事物与已确认信息，沿用全角色共享的 Facts Store | 获准的查询，主线执行按权限修改 | 现有事实领域与版本、事务入口 |
| 日记 | 当天经历的人格化回顾，位于角色工作区 `dailynotes/` | 按日期和文件引用读取 | 沿用现有角色级日常后台维护 |
| 记事本 | 特别要点、简短提醒、技巧及资料索引，使用 Markdown | 通过工作区文件工具直接读取、记录和整理 | 角色与用户按工作区授权维护 |

Agent 主动记录简洁的非事件要点时使用记事本，已确认且适合跨角色共用的信息通过共享事实维护，发生过的事情沿有效来源进入后台事件加工。

任务进度、执行回执、成果版本和验收事实从任务及产物系统取得。心流表达当下判断和行动意图，记事本保存主动要点，事件叙述保存角色亲历及长期认识。

### 7.2 事件只读与事实修改权限

本节定义 Agent 工具侧的目标合同。事件工具保留 `query_event_notes` 等读取入口，移除 `write_event_note`、`revise_event_note` 的主动新增和修订能力。后台事件服务按有效来源提交记忆，角色可以在记事本先保存值得立即记下的要点。

共享事实的所有 Agent 修改入口统一校验真实主 Thread，包括新增、取代旧事实、删除、对象别名新增与移除。校验通过受信执行上下文解析所属角色、Thread 类型、代次及当前授权，事实提交沿用现有事务与幂等身份。

主线身份与场景权限分别校验。据点执行关联角色 MainThread，实际开放的事实操作由该场景工具策略确定。SideThread 和其他任务取得获准的读取能力，公共事实修改由主线承接有来源的请求。

工具目录、实际执行入口、NIT 子调用、应用投影和恢复消费统一采用上述合同。历史记事操作的审计、已受理草稿及已提交内容按实际发布数据和操作回执确定升级处理。

用户记忆管理入口的人工修订、恢复和永久遗忘继续按用户侧领域职责处理，具体操作范围在实施前核对。

### 7.3 记事本目录与日常维护

首版记事本采用角色工作区的 notes 目录，主文件为 MEMORY.md，附页与主文件同级。

```text
角色工作区/
└─ notes/
   ├─ MEMORY.md
   ├─ 相处提醒.md
   └─ 常用操作.md
```

主文件保存简短核心要点和附页索引，其他 Markdown 文件与主文件同级，按实际需要组织。角色通过正常文件工具记录、修改和归整，用户通过对话提出整理要求。

首版记事本按角色共享，由前台主、侧会话及据点按工作区访问权限使用。据点模式的文件入口限定 notes 目录及直接 Markdown 文件，极简模式按上下文规则读取已有主文件作为参考。任务工作区和应用 Realm 继续使用各自授权。

首版每次编译读取主文件最多 16000 字符，交由统一 Region 和最终模型请求预算选择，附页按需读取。内容指纹进入来源和缓存身份，文件版本在合法请求边界固定。

提示词说明记事本位置、主文件用途和附页读取方式。整理时同步主文件索引与相关内容，按用户要求合并重复要点、调整过期提醒，并维护必要来源引用。任务状态通过关联任务读取，笔记正文记录简短提醒及引用。

### 7.4 后台事件与日记

自动聊天加工使用主线对话及其有效据点亲历，后台补记、事件关系维护和日记使用现有角色级调度。总开关、逐角色开关、来源覆盖、失败重试和已生成结果恢复继续作为加工边界。

日记沿现有目录、人格表达、日常生成及失败恢复规则维护。日记与记事本分别表达每日回顾和主动要点。

同一件事跨天或跨场景的发展，由现有事件来源、关系与修订链承接。`EventReflectionService` 已支持同一事件、因果及主题关联、叙述修订与重叠事件归档，`EventMemoryService` 保存修订版本和来源引用。长期积累沿这些既有领域入口持续维护，实际整理与召回效果通过生活场景联动核对。

当前理解与意图由主线心流表达，活动、邀请、关注和任务各自持有业务状态，长期要点与文件引用由角色记事本维护，经历与变化进入事件记忆。角色通过自动召回、主动查询和获准文件读取使用这些资料。

检索围绕当前真实交流、到达事件、关联活动和任务选择相关记忆。引用与关联资料提供检索线索，实际可读内容仍按来源与授权确定。后台整理的来源、模型及生成结果固定后再提交，失败恢复沿原操作继续。

### 7.5 清理工作上下文

增加一个供 Agent 调用的工作上下文清理工具。工作告一段落、准备继续日常交流时，角色可先将值得保留的要点写入记事本，再提交清理请求。

当前工作模式会恢复历史工具调用与结果，聊天和极简模式通过装配策略选择相应资料。独立清理工具进一步记录持久边界，决定之后重新进入工作模式时可恢复哪些过程材料。

目标处理链如下。

1. 服务端解析当前会话、场景、角色及主线代次，核对请求身份与清理范围。
2. 使用稳定执行或请求顺序保存工作轨迹边界与幂等回执。
3. 当前工具协议组结算后，按完整调用／结果组重建下一次合法模型请求。
4. 同步更新运行中的上下文、热轨迹及持久恢复选择，编译器在后续读取时应用该边界。
5. 清理后形成的工作轨迹按新的顺序继续参与后续装配。

清理作用域属于模型上下文装配。原始聊天和执行记录支持审计、按需回读及后台记忆来源，任务取消、历史撤回和记忆遗忘分别使用各自的领域入口。角色长期状态、群聊心流和协作进展从相应权威对象读取。

首版 clear_work_context 限定前台桌面主、侧会话，可在其聊天或工作模式和工具授权允许时直接调用。当前完整原生工具批次作为新过程起点，用户消息、正式发言与最新记事本按对应合同装配。据点及应用场景的清理范围另行细化。

工作轨迹选择变化参与请求缓存身份与预算计算。历史重建、再次切入工作模式和进程重启读取相同的清理边界。

### 7.6 从 Varin 借鉴的接续方式

持续事项由活动和任务领域持有，通过描述和引用连接真实工作，任务与资源 owner 提供实际状态。心流引用相关事项并表达当前理解，主动要点通过记事本保存。

有来源的工作事件通过现有队列进入角色主线处理，可更新心流、整理记事本、推进协作或继续等待。公开消息由本次处理决定，定向回报按原请求者和消费身份结算。持续关注负责条件、接收位置和处理时机。

这些机制结合主线身份与场景资料选择，作为生活参与、后台加工和协作恢复的共同基础。

## 8. 社交、子应用与明确交接

社交应用继续提供平台连接、账号、联系人、参与规则、聊天历史、Realm 心流、工具与发送回执。角色人格、获准的长期状态及长记忆通过资源接口接入，社交事件按来源与可见范围回流。

应用提交的来源材料经获准的主线后台入口加工为事件记忆，公共事实变更由获准主线执行处理，记事本访问沿工作区授权。各入口使用同一套记忆读写职责与来源校验。

据点的角色群聊持续状态关联 MainThread，社交会话使用所属应用的上下文与处理现场。不同场景通过事件、长期记忆和显式交接建立关联。

交接保存 `handoffId`、发起者、接收角色、来源场景、目标场景、目的、选定资料、可表达范围、关联活动或任务、返回位置及回执。

例如用户要求把旅行方案带到据点讨论时，将选定方案及讨论目的形成交接，由据点处理相关活动，再把阶段结果返回原请求位置。交接使用稳定引用与受控快照，恢复时复查来源修订、授权和发送结果。

现有 SocialSessionManager、参与状态机、持久编排、发送恢复、当日摘要、Application 和 Realm 接口继续提供各自职责。`social.tdb` 的后续用途及已发布数据转换单列为待定事项。

## 9. 并发、重启与来源变更

一次状态提交携带角色 MainThread、代次、来源修订、任务或活动关联、预期状态版本和幂等标识。共享状态通过有序提交与版本核验保存，冲突返回当前有效版本供执行方处理。

房间事实、亲历、参与意图、模式转换及相关业务状态按领域事务提交。Outbox 负责可靠通知，KernelScheduler 管理执行、配额与取消，Task 和协作账本保存待办、依赖、消费位置与外部回执。

重启后恢复仍有效的等待与请求，核对真实执行状态及已确认投递。结果不明的外部动作进入核验流程，角色禁用、成员离场、来源撤回和授权变化参与恢复判断。

消息编辑和撤回更新来源有效性，状态贡献沿既有补偿机制处理，记忆保留来源修订或撤回标记。活动取消、分工退出、资料更正和永久遗忘各自保存对应业务事实。

主线重置沿用现有身份与代次合同。新群聊持续事项、进行中活动和协作分工的保留、暂停及恢复范围须在实施前定稿。恢复通过当前代次核验来源、授权和业务状态，再创建后续执行。

逻辑导入、整库恢复、分布式快照和隐私删除覆盖新增状态、活动、分工、亲历、消息及交接引用，保留稳定关联与有效回执。

工作上下文清理边界随所属会话与代次持久保存，导入时按新身份重写引用，恢复时核对实际执行和请求顺序。记事本随工作区文件备份和恢复，正文整理与删除使用文件权限。记忆遗忘涉及笔记的提示或联动范围单列待定稿。

## 10. 升级范围

当前开发中的主线模型使用目标合同推进。升级入口针对实际已发布版本的数据进行核对。

- 已发布旧会话沿既定规则保留原资料并转为 SideThread，每个已登记角色取得空主线。
- 新角色持续字段从空状态开始，既有角色资料、长期记忆和工作区按各自合同读取。
- 旧房间建议默认进入生活模式，既有房间消息和亲历继续作为来源。
- 旧长期记忆保留 ID、版本链及来源，后续由后台整理关联与修订。
- 既有事件工具审计和已受理草稿按原操作身份核对状态，新执行使用事件只读合同。
- 共享事实的既有数据沿原事实库读取，修改入口增加主线身份与场景校验。
- 记事本按实际使用建立目录与主文件，已有同目录内容按工作区文件规则读取。
- 新工作上下文清理边界纳入会话备份及恢复格式，旧记录按兼容规则读取。
- 新活动、分工、来源关联及交接首次实现使用稳定身份、来源与版本合同。
- 已发布配置核对真实字段和单位，自定义提示词取得对应场景的有效资料。

## 13. 核心验收合同

验收聚焦核心行为、数据契约、授权、事务一致性与失败恢复，执行遵循仓库 AGENTS.md。

1. 同一角色跨房间和模式使用同一 MainThread 关联群聊状态，参与资料按对应房间、活动和分工选取。
2. 公共事件保存单份权威事实，各角色取得与发生时在场关系一致的亲历。
3. 私聊、据点、社交及各分工的来源和可见资料按公共契约正确装配，Manifest 记录最终预算与裁剪。
4. 模式启动、暂停、恢复、完成及取消在并发、重试和重启后得到一致结果。
5. 成员接受、实际执行、成果提交及验收分别记录，进度投影反映有效业务事实。
6. 定向信息按其类型记录或调度，处理结果提交后推进消费位置，消息来源与授权主体可追溯。
7. 任务修订、主线代次、来源变化和撤权正确影响迟到提交及恢复请求。
8. 工具与文件操作通过现有能力、资源和审批入口，成员职责按授权执行。
9. 活动、事件记忆、成果与原始来源保留稳定关联，后台开关约束自动加工。
10. 暂停后的迟到结果保存到原任务，显式恢复依据当前有效事实接续。
11. 导入、完整恢复与永久遗忘覆盖新增对象、来源、回执和跨角色公共引用。
12. 新执行中的 Agent 事件查询与召回遵循只读合同，后台事件加工核对真实来源、修订和代次。
13. 事实全部修改入口核验主线身份与场景权限，SideThread 和间接调用按同一合同执行。
14. 记事本主文件与同级附页可通过获准文件工具直接维护，编译按已定规则读取有效版本。
15. 清理边界在下一次合法模型请求、再次切入工作模式及重启恢复时一致生效，工具调用与结果保持完整协议组。
16. 工作上下文清理、任务取消、历史撤回和记忆遗忘分别结算对应领域操作。
17. 同一事件或回报重试沿原消费身份恢复，静默处理保留可追溯执行记录。
18. 当前伙伴可以自然接话，旁听与休息保留角色在场关系，参与意愿和自主授权分别生效。
19. 交流收束、活动生命周期、邀请回应和关注消费按各自来源结算，多项活动可同时持续。
20. 角色在一次真实执行中决定后续参与，程序按事件、合并输入、等待和收束安排认知接续。
