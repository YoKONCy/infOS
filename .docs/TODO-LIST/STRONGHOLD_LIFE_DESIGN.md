# 据点生活参与与事件接续设计

> 状态为待实施设计。本文细化[角色生活与协作总规划](./CHARACTER_LIFE_MEMORY_SCENES_PLAN.md)第 5 节，作为据点生活闭环的实施依据。
> 当前基线包括唯一 MainThread、私聊与据点共享心流、近期原文互通、逐角色自由活动设置、定向回应、房间串行和条件等待。本文新增的交流片段、生活参与状态、活动与事件合同属于目标设计。

## 1. 生活场景与设计目标

据点中的角色长期同住，已经拥有角色身份、共同经历和持续关系。角色可以自然接话、旁听、做自己的事、等待伙伴、兑现约定，也可以主动开启新的交流。

首版闭环为同处、发起、回应与加入、关注或等待、事件接续、自然收束，最后留下各角色实际亲历的来源。

例如，Pero 在客厅听歌并邀请 Nana。Nana 接受后一起听，两人自然聊天。主人进入交流后，话题转向今天的见闻。Nana 说晚安去休息，Pero 结束听歌。之后私聊能接上这段经历，后台按已有开关整理事件记忆与日记。

活动可以同时存在。Pero 和主人聊天时，Nana 可以在旁边看书，佩诺菈继续听歌，遇到相关内容再参与。普通闲聊直接形成交流片段，需要持续公共状态的事情再建立共同活动。

社交运行时提供消息合并、确定性事件匹配、托管等待、步骤回执和失败恢复的参考。据点的参与语义围绕共同生活、当前交谈关系和持续关注设计。

## 2. 当前源码与目标增量

| 领域 | 当前基线 | 本设计增量 |
| --- | --- | --- |
| 身份与心流 | 据点使用角色唯一 MainThread，与私聊共同读写持久心流 | 生活参与、交流和关注记录关联该主线及代次 |
| 普通接话 | 用户发言接续最近交谈者，角色普通分享积累亲历，定向请求触发回应 | 当前交谈伙伴可以自然接话，旁听者依据关注和片段变化获得加入机会 |
| 空闲主动 | 角色配置、空闲机会、房间串行及静默退避 | 以生活场景、已有关注和有效事件选择发起机会 |
| 条件等待 | `finish_task.next_activity` 支持休息、等消息和等已有任务 | 增加邀请、成员出入、活动变化和明确约定等生活条件 |
| 公共状态 | 房间、位置、环境、消息、逐条亲历及 Outbox | 交流片段、生活活动、邀请及有顺序的场景事件 |
| 工具边界 | `group` 通道白名单、有效主线事实修改、目录受限记事本 | 生活行为继续经过场景权限、资源授权与执行审批 |

## 3. 权威数据与归属

| 对象 | 权威内容 | 身份与作用域 |
| --- | --- | --- |
| 角色当前心流 | 当前理解、关注、行动意图与引用 | 唯一 `mainThreadId`、`generation`、心流修订 |
| 生活参与记录 | 当前参与姿态、焦点场景、交流与活动引用 | 主线及代次下的参与关联，附 `roomId` 和来源 |
| 房间 | 环境、实际在场成员和公共事件位置 | `roomId` 与环境、位置修订 |
| 交流片段 | 当前交流的参与者、回应关系、待回答事项与收束状态 | `exchangeId`、所属房间、来源消息与事件 |
| 共同活动 | 活动内容、成员、公共进展和生命周期 | `activityId`、所属房间及修订 |
| 邀请 | 发起者、接收者、活动、回应和有效期 | `invitationId`、稳定来源及目标主线代次 |
| 持续关注 | 关注意图、事件条件、有效期、消费位置与处理回执 | `watchId`、接收者主线及代次、场景或活动 |
| 调度请求 | 本次处理原因、输入范围、接收者和结算状态 | `requestId`、来源、目标主线代次及请求类别 |
| Execution | 实际执行状态、输入快照、调用及发布结果 | 现有 Kernel Execution 身份 |

心流表达角色怎样理解这些事情，活动和等待对象保存业务状态。记事本继续承接主动整理的简短要点，事件记忆与日记沿各自后台合同维护。

角色当前焦点通过 MainThread 下的一份参与记录表达。关注对象可以有多个，按房间、交流和活动引用选择。本次执行的忙闲、取消及占用由既有运行时提供。

房间公共事件保存一份权威内容，亲历关系引用事件发生时的实际可见范围。事件中的行为者和亲历者分别记录。

## 4. 在场、参与姿态与执行

### 4.1 在场

角色位置沿用 `agentLocations`。房间成员资格表达访问与参与资格，实际位置表达此刻身处何处。

进入、离开和环境修改经领域入口提交，写入公共事件及 Outbox。事件保存变更前后位置或环境修订、操作者、来源和当时在场范围。跨房间移动的离开、到达与位置更新共同结算。

用户在房间的出现由明确加入或该房间的真实发言确认，离开由明确操作确认。窗口焦点与页面可见性可提供客户端投影资料，生活约定使用明确来源确认的出现事件。

### 4.2 参与姿态

下表为角色本人的生活参与状态。状态变更携带来源，静默处理也可以提交。

| 状态 | 含义 | 主要接续依据 |
| --- | --- | --- |
| 同处 `available` | 在场，暂时留有交流空间 | 明确交流、相关事件、有效空闲机会 |
| 旁听 `listening` | 关注某段交流或活动 | 对自己的回应、登记关注、片段的有效变化 |
| 交谈 `conversing` | 正在参与一段交流 | 当前回应关系、待回答事项及交流的新内容 |
| 专注 `occupied` | 想先处理自己的事情 | 明确呼叫、已接受的安排及指定关注条件 |
| 休息 `resting` | 暂时休息或离开交流 | 明确输入、约定条件及后续有效空闲机会 |

交谈结束可回到同处或旁听，关注转移可以进入专注，休息结束可重新加入。新的明确输入先进入主线队列，再结合真实执行占用处理。

参与姿态表达当前意愿。用户开关提供自主行为授权，Kernel 提供实际执行状态，这三者分别解析。

| 触发 | 参与状态变化 | 调度结果 |
| --- | --- | --- |
| 角色确认加入交流 | 同处或旁听转为交谈 | 保存参与关联，接续依赖后续真实输入 |
| 角色选择继续听 | 交谈或同处转为旁听 | 保存关注范围，结算本次接话机会 |
| 角色想做自己的事 | 交谈或旁听转为专注 | 结束本人当前接续，保留有效约定与关注 |
| 角色说晚安或选择休息 | 当前姿态转为休息 | 结算当前接续，按活动合同调整参与关系 |
| 明确输入或关注命中 | 原姿态保留到本次处理决定提交 | 保存处理原因，结合执行占用排队 |
| 当前交流安静到期 | 当前交谈转为同处或已有旁听安排 | 程序推进片段状态及有关投影 |
| 主线清空或真实离场 | 原场景参与结束有效调度 | 结算旧代次或旧位置候选，保存原因 |

自动转换仅作用于仍指向该片段或活动、且预期修订一致的参与关联。角色后来转移的焦点以最新提交为准，旧片段继续结算自身状态与来源。

### 4.3 等待与执行

持续关注独立保存条件，角色可以边等 Nana 回来边与主人交谈。同一个等待在匹配、消费或失效后按原身份结算。

执行沿用 Kernel 生命周期。程序领取输入时固定主线代次、场景、输入来源、消息位置和有关业务修订。等待释放执行占用，恢复重新核对这些事实。

## 5. 交流片段与自然接话

### 5.1 交流片段

交流片段组织一段正在发生的相处，保存起始来源、参与者、最近发言者、回应对象、尚待回答事项、相关活动和收束原因。正式消息仍由房间持有权威正文。

片段可包含多名角色和多次独立发言。关联通过消息或事件 ID 表达，现有 `pairId` 继续提供历史来源定位。主线连续交流与生活片段分别保留各自身份。

| 片段状态 | 进入条件 | 后续处理 |
| --- | --- | --- |
| 活跃 `active` | 有当前交流的新内容、有效请求或已接受的接话机会 | 安排有依据的接续，并合并待处理输入 |
| 安静 `quiet` | 当前可执行接续已结算，仍保留在场或关注关系 | 等待新内容、匹配事件或明确恢复 |
| 收束 `closed` | 明确结束、参与者散去，或安静窗口到期 | 保存收束原因与未结事项的最终处理结果 |

片段状态由已提交行为、请求与参与记录计算。单个角色可以结束自己的参与，其他成员的有效交流继续存在。已收束话题后来被重新提起时，建立引用原片段的新交流。

### 5.2 本次参与结果

角色在现有执行中同时提交正式表达和后续参与意图。初稿合同包含以下内容，工具入口与具体字段在实施时统一到现有发言、完成协议和场景适配器。

| 内容 | 用途 |
| --- | --- |
| 正式发言或场景动作 | 公开投递的内容及其种类 |
| 回应来源 | 当前可见的消息、邀请或事件 ID |
| 交流对象 | 当前在场的具体伙伴、当前交流参与者或房间分享 |
| 表达目的 | 分享新内容、提出问题、回答、简短回应或收束 |
| 接续关系 | 明确期待回答、为伙伴留出接话机会、完成本次回应 |
| 后续安排 | 继续关注、转向其他事情、登记等待或结束本人参与 |

服务端根据真实身份、在场关系和消息来源解析目标 MainThread 与代次。公开表达和本次参与决定一起保存，调度依据已成功发布的结果推进。

表达目的用于安排接续。房间状态、活动加入、环境变更和实际操作以领域入口的回执为准。

### 5.3 接话规则

| 输入情况 | 规则 |
| --- | --- |
| 用户点名 | 为真实目标保存明确请求，按目标和入队顺序处理 |
| 用户向房间说话 | 优先接续当前交谈者，其次选择在场且可回应的角色 |
| 角色明确提问或邀请 | 为接收者保存待处理请求，核对其自主配置或已接受安排 |
| 角色向当前伙伴分享新内容 | 当前交流关系中的伙伴取得自然接话候选 |
| 旁听者关注命中 | 按其关注条件和未消费来源安排加入机会 |
| 片段开启或内容转向 | 从已表达关注且空闲的在场角色中选择适合加入者 |
| 简短附和、道谢与结束语 | 结算对应回应，更新亲历和参与姿态 |
| 场景动作或环境更新 | 保存公共事实，交给匹配的关注者或活动参与关系处理 |

同一自然接话来源先挑选下一位候选，选择依据为明确对象、有效等待、当前交谈关系、已登记关注及最近处理位置。相同条件下轮转，避免总由固定角色接话。

角色收到一次自然接话机会后，可以发言、旁听、登记关注或收束本人参与。该结果结算本次候选。其他成员沿自己的真实请求或关注来源参与。

明确用户交流应得到答复、澄清、可追溯的等待安排或处理结果。自主发起与自然接话机会允许静默提交参与决定。

### 5.4 连续交流与收束

新认知执行以尚未消费的输入、匹配事件或有效空闲机会为依据。每次发言保存来源及本次处理结论，回答提交后结算对应请求。

角色可以在回应中提出新问题或补充实质内容，后续请求引用这次新发言。简短附和与收束语推进片段安静状态。相同来源的重试沿原请求恢复。

当当前输入已经处理、接话机会已结算且有效条件处于等待中时，程序使片段进入安静状态。安静窗口到期可直接收束当前片段，活动和约定继续按各自状态存在。

## 6. 共同活动与场景动作

### 6.1 场景动作

据点内的坐下、拿杯子、挥手等动作以简短动作事件呈现，保存行为者、场景、来源和可见范围。声音、位置、环境等结构化状态通过相应领域操作更新。

动作正文表达虚拟场景中发生的事情。系统可读状态由操作回执及事件载荷提供，供参与者后续引用。

### 6.2 活动生命周期

活动按需建立，记录内容、发起者、成员、阶段、必要的公共进展、有关交流片段和来源。听歌、喝茶、文字游戏等共享这份轻量合同，专门玩法可在后续提供领域规则。

| 状态 | 含义与转换 |
| --- | --- |
| 进行中 `active` | 发起者开始活动，成员可加入、暂离或退出 |
| 暂停 `paused` | 明确决定稍后继续，保存当前进展及恢复条件 |
| 已结束 `ended` | 明确结束或最后一位实际参与者退出，保存结束原因 |

成员分别保存参与、旁观、暂离和退出状态。暂停条件、恢复条件和约定按实际活动保存。一次闲聊的安静收束只推进交流片段，活动的结束依据活动自身合同。

发起者退出时，其他参与者可以继续。涉及公共阶段调整时保存当前修订和操作者，邀请与参与者的本人回应分别核对。

### 6.3 邀请与回应

邀请保存活动、发起者、接收者、来源、有效期与状态。状态覆盖待回应、接受、拒绝、稍后、取消及过期。

接受邀请时核对角色、房间访问、活动修订和有效配置，再提交成员加入与邀请回执。稍后回应可以登记具体关注或到期条件。拒绝、取消与过期分别保留原因。

他人的发言可以提出邀请，接收者的真实回应或用户明确安排确认参与。参与结果通过来源及预期修订处理重复与并发回应。

## 7. 事件与持续关注

### 7.1 事件种类

| 事件 | 典型来源 | 主要消费者 |
| --- | --- | --- |
| 正式发言 | 用户、角色已提交消息 | 明确接收者、当前交流及关注者 |
| 进入或离开 | 实际位置变更、用户明确出现 | 有效在场者及对应关注 |
| 环境变化 | 环境领域操作回执 | 匹配该变化的活动和关注 |
| 邀请回应 | 接受、拒绝、稍后、取消或过期 | 邀请双方及相关活动 |
| 活动变化 | 加入、退出、暂停、恢复、阶段调整或结束 | 有关成员与关注者 |
| 约定到期 | 已确认约定的一次性到期事件 | 约定参与者 |

事件携带稳定 ID、房间、种类、发生时间、操作者、来源消息或执行、关联对象、修订及当时的可见范围。请求和亲历可以引用同一公共事件，各自记录处理位置。

### 7.2 关注条件

关注保存接收者主线与代次、意图、来源、适用场景、结构化条件、有效期、已观察位置及消费回执。

首版条件包含特定人的消息、被提及、某人进入指定房间、某项邀请的回应、指定活动的状态变化、明确环境字段变化和约定到期。

条件先按事件种类、对象、位置、修订和可见范围确定性匹配。匹配输入携带角色此前记录的关注意图，由角色在实际执行中理解语境。多个相关事件合并进入同一次输入。

同来源同目的的关注采用稳定身份更新。关注可以在处理后完成，也可以依据当前真实事项更新条件。事项结束、取消、离场或有效期到达时按合同结算。

### 7.3 新事件与原安排

角色登记后续安排时可以选择保留、取消未执行部分或结合新内容重判。原有正式发言和已确认操作保留实际结果，后续安排只处理尚待执行的部分。

确定内容的延后表达沿用固定发布身份。需要到时重新理解的事情保存意图和条件，在到期或匹配后产生一次处理请求。纯状态到期、邀请失效和片段收束可由程序直接结算。

## 8. 调度、配置与调用节奏

### 8.1 确定性选择顺序

调度器按以下顺序检查候选。

1. 核对角色、MainThread 代次、来源、在场范围、场景授权和对象当前状态。
2. 合并同一接收者、同一来源关系中的待处理输入，保留每项来源及独立结算身份。
3. 优先处理明确用户输入。私聊与据点的明确用户输入在同一优先级按受理顺序安排。
4. 处理角色的有效请求及已接受的安排，再处理命中的关注和自然接话机会。
5. 角色与房间空闲时，依据有效配置、已有关注及空闲调度提供自主发起机会。
6. 领取后固定输入快照，交给角色执行，后到输入保留到下一次安全边界。

房间沿用串行发布与执行组织，角色跨私聊和据点共用主线注意力。新的明确用户输入使自主回合按既有安全边界让出，工具回执和已发布内容按实际结果保存。

这份选择顺序构成程序侧的行为选择树。每次扫描只领取当前符合条件的处理分支，执行中产生的后续决定重新形成有来源的状态或事件。角色的语义判断发生在被选中的真实执行里。

### 8.2 自由活动与参与意愿

全局和每角色配置沿用已确定合同。主动模式支持 `off / companion / autonomous`，据点自由活动独立支持继承、开启与关闭，全局自由活动默认关闭。

用户明确交流按用户请求处理。角色自行发起、回应伙伴邀请及自然接话机会按该角色有效自由活动配置处理。已接受的用户安排携带明确的参与与接续授权，按该安排处理。

参与姿态只调整当前关注与处理方式。修改自由活动配置时，待执行自主候选和关注按来源暂停或结算。重新开启后根据当前在场、活动和新输入重新选择机会，明确请求保留原处理结果。

### 8.3 安静与节奏

安静时段约束自主发起和普通旁观机会，明确输入及已接受安排分别按各自合同处理。角色可以登记休息结束条件和约定，由现有调度发现到期事项。

本设计通过以下机制控制模型调用。

- 程序先筛选真实接收者，普通场景事件先进入亲历和观察资料。
- 连续输入与同一关注命中的变化合并处理。
- 等待持久保存并释放执行占用。
- 简短回应、收束语、过期和已完成来源推进结算。
- 空闲时轮转角色，静默结果延长空闲等待，有效新事件可提前恢复。
- 角色在一次执行中顺便决定后续关注、等待和收束。
- 已确定步骤由程序执行，需要理解新内容时交回角色。

模型参与依据有效输入和生活状态，调用总量沿既有 Execution 防护处理。具体收集窗口和安静窗口在实施接线时结合现有配置确定单位与默认值，作为节奏参数维护。

## 9. 提交、恢复与生命周期

### 9.1 提交与消费

房间消息或事件、当时可见关系、领域状态变化、本次参与决定与 Outbox 在对应领域事务中提交。涉及多个领域时保存稳定操作身份与待完成步骤，恢复按原回执推进。

执行输入保存来源范围与相关修订。请求只有在参与结果及应发布内容已提交后才完成消费。重复投递、Outbox 重试和周期恢复复用同一请求与发布身份。

程序结算到期状态时也保存原始原因。延后执行发生前复查当前角色配置、位置、目标状态和主线代次，失效结果保留为终态记录。

### 9.2 用户打断、移动与重启

用户打断时先保存实际完成结果，再让出角色执行占用。生活活动和有效关注按其状态保留，后续调度根据新情况选择接续。

房间移动遵循当前执行已固定的场景及公开目的地，新的位置在后续执行生效。离场会结算当前接话候选，并按活动合同调整成员状态。关注可显式以等待某人到达为条件。

重启恢复有效请求、已接受安排、关注及已发布回执。到期事项根据当前时间、来源和对象状态结算，再决定是否需要认知接续。停机期间的场景进展根据实际保存的事件恢复。

### 9.3 主线清空、导入与遗忘

主线清空使旧代次的候选、请求和关注结束有效调度。公共消息、环境和活动保留各自来源，相关成员的旧代次参与标记为已中断，后续通过当前代次的真实加入或明确恢复建立新关联。角色长记忆、文件和设置沿既有重置范围保留。

逻辑导入重写角色与主线引用，恢复公共活动及历史回执，新的认知接续根据导入后的有效身份重新建立。完整恢复和分布式快照恢复同一套领域数据，启动时核对代次、修订、来源与未完成状态。

撤回、编辑及永久遗忘通过稳定来源定位受影响的片段、参与贡献、请求、亲历和派生记忆。来源撤回使对应调度失效，公共对象依据仍有效的贡献和操作回执重算或保留来源变化标记。

## 10. 上下文、记忆与投影

据点执行通过 ContextCompiler 装配角色身份、共享主线心流、当前房间可见原文、参与姿态、当前交流、活动及触发关注。按本次处理的相关性选择资料，来源进入 Manifest。

主会话与据点近期原文互通继续采用当前场景正式消息数量的二分之一，向上取整，空窗口沿既有默认基准处理。社交聊天资料与心流继续使用所属应用的作用域。

房间投影提供实际在场者、当前活动、简短公开进展、邀请与相关动作。角色的私有心流和关注意图按原有可表达范围装配，公开正文由角色结合当前场景决定。

正式消息与动作事件提供可追溯亲历来源。事件记忆由后台加工，日记沿日常维护，记事本保存主动要点。活动的权威状态由活动入口读取。

新增动作及活动事件需要接入后台来源选择和覆盖位置。消息与事件共同表达同一经历时，使用关联引用去重，后台提交保存实际采用的来源与版本。后台开关、遗忘截止及来源撤回继续约束加工和重试。

## 11. 实施接线与推进顺序

状态转换、事件匹配、来源核验和参与授权由服务端负责。客户端提交操作意图并读取投影，Gateway 通知数据变化。客户端与 Electron 能力继续经既有能力节点接口接入，分布式恢复以服务端权威状态和操作回执为依据。

## 12. 核心验收场景

以下场景用于核对核心语义、数据正确性与恢复合同。

1. Pero 分享新内容后，当前交谈伙伴可以自然回应，回应来源与参与配置正确。
2. 一句道谢完成原请求并使交流安静，后续相关新内容可以开启新片段。
3. Nana 旁听期间保留有效亲历，登记的兴趣命中后带着真实来源加入。
4. 同一房间同时听歌、看书与聊天时，各活动成员、进展及关注各自正确。
5. 邀请接受与取消并发时按预期修订结算，成员加入与回执一致。
6. 等待某人进入的条件只消费有效到达事件，重试复用原处理身份。
7. 私聊插入时角色交出自主执行占用，已发布内容与活动进展保持真实结果。
8. 同一主线跨私聊和据点使用同一心流，活动、约定和记事本按各自权威来源读取。
9. 自由活动关闭与重新开启时，用户明确请求、已接受安排和自主候选按各自来源处理。
10. 短暂安静、过期及片段收束通过程序结算，认知接续具有有效输入或空闲来源。
11. 发布成功后进程中断，恢复能结算原请求，已发布内容保留原发布身份。
12. 主线清空后旧代次停止生效，公共活动和历史来源保持可追溯，新参与使用当前代次。
13. 导入、快照恢复和永久遗忘覆盖新增对象及跨对象引用。
14. 角色的公开表达、场景操作和实际加入分别对应真实权限、回执与参与来源。
15. 角色转移关注后，旧片段的安静到期事件只结算原片段，当前参与关联保持最新修订。
