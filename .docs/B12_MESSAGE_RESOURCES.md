# 消息资源与文件引用

## 入口

- 主 Agent 使用一个 `send_file` 工具，聊天模式可用；主动陪伴与到期跟进仍沿用各自的能力范围。
- `source` 接受工作区路径、HTTP/HTTPS 地址或 `attachment:附件ID`，`caption` 为可选说明。
- 发送会保存资源副本，不依赖原文件或签名链接以后是否仍可用；正文引用读取当前资源。
- 资源只向模型返回名称、类型、大小、附件 ID 和来源，不把文件正文或二进制塞进工具结果。

## 引用

### 按需读图

- 文件工具组增加 `read_image`，参数为 `file_path`，支持工作区路径、设备绝对路径、`attachment:ID` 和公开图片 URL。
- 支持 PNG、JPEG、WebP、GIF，单图最多 20 MB；根据文件签名校验类型，在线来源复用公开地址校验与受限下载。
- 主模型启用视觉时，原图以高精度多模态内容进入当前轮；否则使用已配置的多模态转述模型，均不可用时不向模型开放该工具。
- 历史消息进入上下文时，保留图片名称和附件 ID，需要核对细节时再调用工具；用户上传和 Agent 发送的图片均可引用。
- 附件须属于当前角色；桌面会话可回看该角色其他会话中已绑定的附件，其他通道只读当前会话附件。已撤回附件拒绝读取。
- 原图仅保存在内部工具元数据和当前轮视觉内容中，不进入工具正文、日志、SSE 或后台检查点；本轮最多保留最近四张文件原图，释放后保留来源供再次读取。
- 文字转述归档关联当前对话轮次，撤回时同步删除；`run_script` 不承载图片，须直接调用 `read_image`。

### 文件引用

```markdown
[报告](workspace:reports/result.md#L28)
[附件](attachment:附件ID)
[演示](resource:https://example.com/demo.mp4)
[文档](arca:文档ID)
```

独立一行的引用显示为文件签，行内引用显示为小标签。代码块不解析成引用卡片。

- 工作区文本引用聚焦主应用工作区的既有编辑标签，未打开时创建标签，支持行号定位。
- 图片、视频、音频和 PDF 进入资源预览；普通文件提供下载。
- 在线网页、在线文本和在线 PDF 引用进入浏览器标签页；Arca 文档进入 Arca 的文档路由并复用应用标签页。
- 发送卡片默认查看附件副本，额外的源文件入口打开当前来源。
- 任务工作区文件通过任务来源预览，不把任务路径误解释成日常工作区路径。

## 用户音频与录音

文件选择、拖放和粘贴共用音频上传链路，识别 WAV、MP3、AIFF、AAC、Ogg、FLAC、M4A 和音频 WebM。服务端检查实际容器头，WAV 的时长、采样率与声道写入已有附件元数据；其他格式保留可识别的 MIME。伪装或无效的音频按普通原件保存，不将其当作原音发送。

输入栏录音按钮及音频菜单支持原音录制、停止、取消和 HUD 电平/计时；最长录制两分钟。浏览器录音在本地转换为单声道 24kHz PCM16 WAV，上传后进入可试听、删除或重试的附件草稿，由用户确认发送。既有 ASR 入口继续将录音转写为可编辑文字。两者共用采集内核，切换会话、角色或卸载组件会中止旧处理并释放麦克风。

当前轮是否发送原音由模型卡片手动开关和实际 Gemini 协议共同决定，规则见[服务商连接与模型卡片](B22_PROVIDER_CONNECTIONS.md#gemini-原生音频输入)。历史保留音频名称及附件引用，审计和工作检查点不重复保存 base64 原音。

## 后端

- 复用 `message_attachments`，资源来源、说明、调用标识保存在已有 `metadata_json` 中，不增加表或运行时迁移。
- `ResourceService` 负责校验当前角色、会话和工作区，下载与类型识别，随后交给 `AttachmentService` 保存。
- 完成或中断回合时，将成功交付的附件绑定到 Assistant 消息；消息撤回沿用已有附件软删除。
- 实时工具结果和持久 Projection 都映射为资源卡片，避免与工具调用详情重复展示。
- 内容接口支持流式读取、HEAD 和单段 Range，播放与拖动不需要读取整个视频。
- 文本预览最多读取 128 KB；文件下载保留完整内容。SVG 沿用图片／文本预览，HTML 通过受限网页预览入口打开。

### 工作区网页预览

- 模型先直接调用 `expand_advanced_tools`，再使用 `browser_open_url` 打开 HTML/Three.js 页面，并可调用 `browser_screenshot` 核对真实渲染。
- `url` 接受工作区 HTML 相对／绝对路径、`workspace:`、`file:` 与 `attachment:` 引用；资源服务核对角色、会话和工作区边界后签发短期预览票据，不把文件路径拼成远程网址。普通 HTTP/HTTPS 网站保持原导航。
- 工具和前端文件入口共用同一个 `HtmlPreviewService` 与票据表，保留相对资源、查询参数与片段，任务附件保留原任务工作区。取消后不继续发起导航。
- `open_application` 只启动已安装的软件；收到网页或 HTML 目标时，在调用桌面能力前返回浏览器工具指引，不自动抢占用户桌面或绕过高级工具开关。

### 限制

- 单文件最多 100 MB，同时最多处理 4 个资源。
- 在线下载总时限 90 秒，最多 4 次重定向；每一跳重新校验公开地址并固定 DNS 结果。
- 不携带用户的浏览器登录态；需要登录、链接过期或超限时返回失败。
- 本地来源限制在当前 Agent 的工作区；已有附件须属于当前角色。
- 视频和音频能否播放仍取决于客户端支持的编码，保留原文件下载入口。

## 社交

- 内置 Social Realm 使用收窄的 `SocialResourcePort`，复用 `send_file` 的参数，目标账号和会话从可信本轮上下文取得。
- 工作区文件只允许发送给绑定主人的私聊；群聊及其他私聊可以发送公开在线资源。
- NapCat 图片、视频、语音走消息段，普通文件走上传接口；检查平台返回的 `status` 和 `retcode`。
- 同一社交回合内相同来源和说明复用投递结果，避免工具重复调用造成重发。
- 平台发送确认后的历史记录失败不反向报成投递失败。
- 发送结果未确认时暂停本轮继续投递，交给用户确认，避免把超时当成确定失败而自动重发。
- 音频附件使用独立媒体播放器，不进入桌宠的口语 TTS 通道。

NapCat 接口依据：[官方 API](https://napneko.github.io/onebot/api)。

## 维护入口与失败边界

资源经过附件保存、消息引用、当前轮多模态投影和客户端预览四个阶段。原始文件存在不等于模型已收到像素/音频，平台接受发送也不等于对方已读。模型输入能力、引用可访问性与投递回执必须分别判断。

后端入口位于 `packages/backend/src/services/attachment/`；HTML 预览票据由其中的 `htmlPreviewService.ts` 管理。工作区预览见 [B14](./B14_WORKSPACE_FILE_PREVIEW.md)，Gemini 模型开关与连接协议见 [B22](./B22_PROVIDER_CONNECTIONS.md)，社交发送确认见 [B21](./B21_SOCIAL_CAPABILITIES.md)。修改资源传递时保护作用域、大小限制、取消和未确认发送，不把失效引用静默当成空内容。
